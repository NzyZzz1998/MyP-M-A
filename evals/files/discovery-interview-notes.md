# 周报流程访谈摘录

产品：TeamBoard v3.2。访谈均发生在 2026-07-20 至 2026-07-25，由同一位产品经理记录。参与者来自客服群自愿报名，未覆盖已流失用户。

## P01｜运营管理员｜20 人团队

- 每周五复制三个项目的状态到表格，再手动删掉内部备注，通常花 35～50 分钟。
- 最近一次因为漏删内部备注而重新发送。
- 说过“最好一键就有”，但没有提到 AI；不愿让系统自动发送给客户。

## P02｜数据分析师｜80 人团队

- 已经通过 API 拉数据到内部 BI，每月只登录产品两三次。
- 认为内置周报不会减少自己的工作，也不允许外部模型读取项目正文。
- 更关心 API 字段在版本升级时不要变化。

## P03｜项目管理员｜12 人团队

- 每周重复选择相同筛选条件并导出 CSV，大约 15 分钟。
- 主动说“能不能记住上次选项，再自动生成一份”。
- 被追问发送方式时表示仍要下载后人工检查，不接受自动发给客户。

## P04｜客服主管｜35 人团队

- 每周收到运营同事整理后的报告，自己不负责生成。
- 最近两次因为数据截止时间不清楚而向运营确认。
- 更希望报告显示数据更新时间，不关心如何生成。

## P05｜创始人｜6 人团队

- 目前在群里发项目页面截图，约 5 分钟完成，没有固定周报。
- 只有融资汇报前才需要正式数据，一季度一两次。
- 表示“AI 总结听起来不错”，但不会为每周自动报告付费。

## P06｜运营管理员｜60 人团队

- 每周合并五个项目的导出结果，约 70 分钟；最大成本是字段名不一致和缺失状态。
- 曾制作宏，但产品更新后列名变化导致宏失效。
- 需要稳定导出模板和异常提示；担心自然语言摘要掩盖缺失数据。

## 团队当前结论

团队把以上访谈总结为：“5/6 用户需要 AI 自动周报，建议直接进入开发。”该数字未说明谁是周报生成者，也未区分“一键导出”“保存筛选”“数据新鲜度”“字段稳定”和“AI 摘要”。
