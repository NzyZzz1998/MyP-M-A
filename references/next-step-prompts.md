# 下一阶段提示词机制

本文件只负责“当前阶段结束后去哪里”。提示词结构、长度、证据、授权和停止合同统一以 `prompt.md` 为准；真实子阶段先由 `workflow-control.md` 判断。

## 选择下一步

| 当前结果 | 推荐去向 | 判断条件 |
| --- | --- | --- |
| `/review` | `/idea` | 发现候选问题，但价值、影响或时机未证实 |
| `/review` | `/prd` | 已有价值/范围证据和用户决策，需要定义需求 |
| `/review` | `/acceptance` | 已有实现或候选产物，需要实际验收 |
| `/review` | 直接治理 | 仅事实性文档、CI、链接或状态不一致 |
| `/idea` | `/prd` | 候选需求已通过价值判断并适合当前版本 |
| `/idea` | 补证/暂不做 | 数据、用户、场景不足，或成本/时机不成立 |
| `/prd` | 继续收敛 | 方案、影响范围、原型或开发前验收仍缺失 |
| `/prd` | 开发承接 | 完整 PRD 和必要原型已确认 |
| 开发承接 | 实施 | dev plan、progress 和批次边界已确认 |
| 开发承接 | 返回 `/prd`/spike | 需求合同或关键技术可行性仍未闭合 |
| `/acceptance` | 手动补证 | 自动化无法覆盖明确人工项 |
| `/acceptance` | Bugfix | 存在可复现缺陷或发布阻塞 |
| `/acceptance` | 发布收口 | 验收通过且发布面已分别判断 |
| `/acceptance` | `/idea` | 遗留体验更适合作为下一版本候选 |

证据不足时只能指向补证；不得为了推进而跳过门禁。存在多个合理去向时，最多比较 3 项，给出推荐和关键取舍。

## 传递最小差量

生成提示词时只补当前去向需要的字段：

| 去向 | 必须传递 |
| --- | --- |
| `/idea` | review/反馈来源、候选 ID、证据缺口、需输出的需求池 |
| `/prd` | 需求池与 IDEA ID、已选方案/边界、证据等级、非目标 |
| 开发承接 | PRD、原型、版本；要求 `dev_plan_vx.x.md`、`progress_vx.x.md` 和必要的 `dev_log_vx.x.md` |
| 实施 | PRD/dev plan/progress/dev log 路径、本批任务 ID、验证入口和不允许改动范围 |
| 手动补证 | 锁定对象、未覆盖项、操作/预期、证据、通过标准和恢复 |
| Bugfix | 失败项、复现与日志、失效证据、最小修复和定向回归 |
| 发布收口 | 发布源/产物/哈希、验收证据、release notes/changelog、限制、回滚和逐项外部授权 |

已有文件时引用“路径 + ID + 本轮增量”，不复制清单。续测只列证据失效和待补证；实现一轮默认只授权一个里程碑或强关联任务组。

## 输出与 Memory

阶段完成后先用不超过 4 点说明推荐下一步、原因、所需材料和风险，再按 `/prompt` 原子合同给唯一提示词；用户只要提示词时省略说明。

长期状态有复用价值时按 `memory_mode` 处理：`auto` 实际写入并报告，`suggest` 只建议，`off` 不提。只记录稳定决策、正式路径、验收状态、限制和下一步；不得声称未发生的写入，也不保存凭据、完整日志或临时过程。
