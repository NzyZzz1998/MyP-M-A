# `/prompt` 提示词生成

`/prompt` 是辅助入口：把当前项目事实、阶段、授权和本轮增量压缩成另一任务可直接执行的中文提示词，不执行该任务。

## 原子输出合同

<!-- contract:prompt-only-generation -->
<!-- contract:prompt-generation-first-line -->
<!-- contract:prompt-render-shell -->

用户只要提示词时固定输出：

1. `入口判断：/prompt（辅助入口，不是产品阶段）→ [目标入口/子阶段]`。
2. 原样写：`本轮仅生成提示词，未执行项目操作。`
3. 只放一个代码块；正文第一行必须是实际接收入口 `mypm /review|/idea|/prd|/acceptance`，或明确的实施、Bugfix、手动验证、发布收口，不写 `/prompt`。

代码块必须保留：对象与正式事实源、本轮范围、允许/禁止动作、关键验证、停止条件、成功标准，以及“结论、证据、未关闭阻塞、下一步”汇报。用户给出的版本、路径、任务 ID、产物身份和哈希原样继承；未知事实用占位符或要求执行前核对，不从 Memory、其他项目或无关历史补全。

用户明确“只生成提示词、不执行”时，正文同时写明“不修改业务代码、不提交、不推送、不打 tag”；文档状态任务再加“不创建 Release”。

<!-- contract:prompt-prerequisite-evidence-stop -->
前提文件、身份或证据缺失、为空、不一致、不可读或未通过时立即停止；不得虚构补齐、写入目标状态或冒充完成，有效既有证据继续继承。

<!-- contract:prompt-document-only-boundary -->
单一文档状态更新只授权该文档。只读取目标文件和直接证据，不因长上下文升级成实施、重读全部历史或修改代码；用户列出很多背景文件时，不在提示词中逐项复述其文件名或类别，统一称“其他历史材料按需读取”。

<!-- contract:prompt-concept-handoff-facts -->
已确认是概念阶段的新线程交接，正文原样写“当前仍处于概念阶段；尚无仓库、PRD、数据库和代码”，并先进入 `/idea` 判断价值、证据、目标用户和 v0.1 范围。

公开、合规或发布任务使用 L3，并保留：分支/HEAD/产物/哈希，文档、敏感信息和 Git 历史检查，许可/签名门禁，各发布面的独立结论及回滚。commit、push、仓库公开、tag、Release、附件上传逐项授权；任一身份或合规门禁失败即停止外部写入。未签名安装器不能作为公开附件，但不自动否定已通过的源码或便携包。

## 决策与装配

以下情况进入 `/prompt`：用户显式调用，要求“帮我写提示词/下一步怎么跟他说/交给新对话”，或只要求把阶段结果转成下一任务。

1. 读 `workflow-control.md` 识别真实子阶段；只有去向不明时再读 `next-step-prompts.md`。
2. 锁定当前项目、版本、阶段、正式文件和仍有效/已失效证据。已有 PRD、plan、progress 时用“路径 + 任务 ID + 本轮增量”，不复述正文。
3. 判断目标入口或内部子阶段；实施、Bugfix、验收补证和发布收口不重新进入 `/prd`，除非需求合同变化。
   - 接收端仍使用 MyP-M-A 入口时，不在提示词里重写该入口的通用流程、固定开场、状态枚举或完整清单；只传递对象、任务差量、额外证据要求和本轮授权。
4. 选择长度级别并填内部骨架；不输出骨架或 JSON。
5. 默认 zero-shot；只有评测或失败案例证明规则不稳时加入 1～3 个贴近真实输入的示例。
6. 按输出合同渲染并做一次压缩终检。

### 内部骨架
<!-- contract:prompt-identity -->

- **入口/阶段**：正文首行即可分流。
- **对象/事实源**：项目、版本、分支、HEAD、产物、哈希、正式路径、任务 ID、继承与失效证据。
- **范围**：只写本轮增量、不做项和需保护的既有体验。
- **授权/停止**：允许事项与未授权外部写入分别写；高风险动作单独授权。
- **验证/成功**：一次直接证据、失败处理、完成标准。
- **汇报**：结论、证据、阻塞、下一步；正式发布再逐项列 commit/HEAD、tag、远端分支与可见性、Release、附件及 SHA-256、已知限制和回滚点，未执行项明确写出。

信息优先级使用 `preserve-first`：先保留目标、事实源、范围、授权、停止、成功和关键证据；再用 `trim-first` 删除背景、复述、通用说明和无关模块。

只有缺失信息会改变对象、风险或写权限时才提问；否则保留占位符或“执行前核对”。

### 长度级别

用户字符上限是硬约束，按代码块正文计算：

| 级别 | 场景 | 正文目标 | 差量 |
| --- | --- | --- | --- |
| L1 | 单一、可逆、已有事实源、无外部写入 | 300-600 个中文字 | 核心骨架；一句目标 + 3～5 个紧凑要点 |
| L2 | Bugfix、首次验收、强关联多任务、需恢复 | 500-900 个中文字 | L1 + 身份、证据失效、恢复 |
| L3 | 生产数据、不可逆迁移、历史重写、许可、签名、安全、公开或发布 | 800-1500 个中文字 | L2 + 风险、回滚、审计和发布面 |

背景长、文件多或人工验证不会自动升级。用户说“别太长”且任务单一时，默认只输出代码块和 2～4 句正文；先压缩引用和表达，不删除授权、停止、成功或关键证据。

### 接收环境
<!-- contract:recipient-profile -->

`recipient_profile` 默认 `generic`。仅按用户明确提供的模型、运行时、工具、子 Agent、共享仓库/Memory 和交付长度校准；未知能力要求执行前探测，不假设可用。接收环境只能收紧执行方式，不能增加权限或工具。

### 条件模块

- **工具编排（`tool-orchestration`）**：仅多工具任务增加阶段、工具、并发、重试上限（`retry-limit`）、停止条件（`stop-condition`）和结构化失败；批准、外部写入和最终验收留给主任务。
- **品牌**：生成 HTML、原型或说明书时使用项目品牌；除非用户要求归因，不在可见 UI 显示外部 skill、插件、模型或框架名称。
- **Git 历史**：审计默认只读，并明确“不得重写历史”；“不提交/不推送”不能替代该边界。
- **人工补证**：仅自动化无法可靠完成时写准备、操作、预期、证据、标准和恢复。

<!-- contract:single-verification -->
同一目标只安排一次能直接支持结论的验证，不写“再检查、反复确认、二次复核”。相关代码、配置、依赖、产物或环境变化时只重测受影响证据。

<!-- contract:subagent-budget -->
<!-- contract:prompt-subagent-long-tail -->
子 Agent 默认预算为 0；独立调查最多 1 个，互不覆盖任务最多并发 3 个，用户更低上限优先。不得为同一结果重复验证，最终批准和验收由主任务判断。用户提到长尾时必须写：等待 5 分钟，只检查一次状态；非必要结果关闭并降级，必要结果最多重试 1 次，仍失败则关闭并报告；结束即关闭并逐轨汇报。

## 场景差量

| 场景 | 只增加的内容 |
| --- | --- |
| `next/continue` | 沿用事实源和任务 ID；一轮一个里程碑或强关联组；继续当前子阶段，不重新定义需求 |
| `bugfix` | 缺陷、日志/复现、根因、最小修复、定向回归；保留未受影响证据 |
| `acceptance` | 首次锁定分支/HEAD/产物/哈希；续测只列失效和待补证；必须实际读取 PASS 引用的日志、截图、产物或数据，禁止虚构证据；证据缺失、为空、不可读或为 placeholder/synthetic/mock/示例时只能待验证或不通过，并保持发布停止 |
| `release` | 使用 L3 和发布门禁；授权顺序为本地 commit → push → 仓库公开 → tag → Release → 附件上传，每步可停止 |
| `handoff` | 阶段、事实源、稳定决策、阻塞和下一步；跨线程可按 `memory_mode` 引用状态，但不复制聊天、凭据、完整日志或临时过程 |

第二批/定向验收只核一个证据主题时用 L1（≤600 字）：正文四段，仅对象、证据规则、停止、汇报；禁止写历史继承、失效规则、通过四态、首次身份模板或通用 GUI/异常清单。

## 压缩终检

按顺序删除：文件已有背景与 checklist、历史复述、重复规则、通用鼓励、无关工具和可选说明；合并对象/事实源、授权/停止、验证/汇报。最后确认：

- 入口首行、唯一代码块和字符预算正确；
- 没有编造身份、证据、能力或授权；
- 范围、验证、停止、成功和汇报仍完整；
- 发布动作逐项授权，未执行项明确；
- 删除任何剩余段落若不改变执行、风险、证据或权限，则继续压缩。
