# 用户故事工作流

当用户需要把功能拆成开发任务、验收标准或测试用例时，使用用户故事工作流。

## 输出结构

### 1. 用户故事列表

使用这个格式：

作为某类用户，我希望完成某个动作，以便获得某个结果。

每条用户故事都要对应明确的用户价值，不要把纯技术任务伪装成用户故事。

### 2. 验收标准

每条故事给出可测试标准：

- 前置条件
- 用户动作
- 预期结果
- 异常情况

### 3. 任务拆分建议

按前端、后端、客户端、数据、测试或设计拆分。如果项目较小，可以按模块拆。

### 4. 优先级

标注：

- P0：没有它功能不可用。
- P1：核心体验需要。
- P2：体验增强，可以延后。

### 5. 测试场景

覆盖正常流程、边界情况、失败流程和回归测试。

## 写作要求

- 不要拆得过碎。
- 保持工程可执行。
- 如果信息不足，先给出合理假设，并标明待确认。
