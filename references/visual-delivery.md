图形只表达已经锁定的事实，不生成新事实。先判断读者要核验什么，再决定是否出图；表格或文字更清楚时不出图。

## 0. 发送前硬检查

1. 先写 `required_artifacts`；数值和语义均承重且用户要求本轮出图时，固定为 `decision_chart + semantic_diagram + fallback`，逐项标 `delivered / blocked`，少一项不得称完成。用户要求错误合图时拒绝该排版约束，但事实充分且 Mermaid、本地 HTML/SVG 等安全降级可用时仍须当轮交付拆分后的承重图；可选工具不可调用不构成阻塞。
2. 数值源须逐行读取并记录 `source_row_count`。未变换时，原始冻结数据集合须与图表事实映射及图中可见集合相等；有筛选、聚合、派生或抽样时，全部原始行仍须可追溯，并记录纳入/排除理由、公式和转换后行数，此时要求 `转换后冻结数据集合 = 图表事实映射集合 = 图中可见集合`。不得未声明抽样、遗漏或只读首行，也不得因用户称谓与字段名不一致而丢弃已锁定数值；保留原字段并标注语义差异。
3. 语义图先枚举来源中的全部承重关系，记录 `source_proposition_count` 及每条 `P-ID / 原文主语 / 关系 / 原文宾语 / locator / included|excluded / 理由`，不得只为已画出的边补账本；要求完整地图时不得静默排除。每条可见边须一对一引用一个 included P-ID，并原样继承其主语、关系和宾语；没有 P-ID 就不画边。复合句 `A 调用 B，并读取 C` 未明确改换主语时，只能映射 `A -> B`、`A -> C`，不能改成 `B -> C`；同名、泛指、路径模式或具体文件默认是不同实体，只有来源明确给出别名或同一性时才能合并。不得把相邻句、并列对象或职责描述串成新链路。最终记录 `node_count / edge_count / mapped_node_count / mapped_edge_count`，满足 `来源 P-ID 集合 = included + excluded`、`included P-ID 集合 = 图中边/属性 = 边映射`、`图中 N-ID 集合 = 节点映射集合`、`图中 E-ID 集合 = 边映射集合`；图、账本、结论摘要和静态降级中的同一命题必须保持同一主语、关系、宾语。每个 N/E 项各有独立、可回到文件行或章节的 source locator，发送前回读定位并逐边、逐段对照 P-ID。

只有承重事实/来源本身缺失，或所有安全本地表达均不可用时，才可把承重图标为 `blocked`。其他失败须先修正；不能用表格、文字或“后续再画”冒充缺失的承重图。

## 1. 选择通路

| 承重事实 | 通路 | 典型产物 | 核验对象 |
| --- | --- | --- | --- |
| 数值、单位、分母、时间窗、筛选、聚合 | 决策图表 | 比较、趋势、分布、关系图 | 每个值、标签、单位、变换 |
| 节点、边、方向、条件、状态、顺序、职责、基数 | 语义图解 | 架构、流程、状态、时序、ER、泳道、数据流 | 每个节点、边和语义 |

- 混合任务先锁定主要问题并执行上述 `required_artifacts` 检查；表格/文字只作附加降级，不能替代其中一图。
- 证据不足时停止补全。未知项保留“未知/待确认”，推断与假设必须区别于事实。
- `/review` 项目地图和 `/prd` 流程、状态、ER 优先走语义图解；冻结数值的 `/idea`、`/review`、`/acceptance` 可走决策图表。

## 2. 事实冻结与映射

生成前建立事实映射。语义图先把来源逐句拆为原子命题账本，再由账本生成节点和边；命题、实体同一性和可见边是三层独立记录，不能从最终图反向补账本：

| P-ID | 原文主语 | 关系 | 原文宾语 | source locator | 覆盖 | 理由/实体同一性证据 |
| --- | --- | --- | --- | --- | --- | --- |
| P-001 |  |  |  |  | included / excluded | 明示别名 / 不同实体 / 未知 |

先按来源逐句完成命题覆盖，再决定哪些命题适合画成边或节点属性；excluded 必须说明不影响当前问题的依据。要求“全部”“完整”或承重架构时，承重命题必须 included。同一 P-ID 只能生成相同主语、关系和宾语的边。`reference`、reference 文档集合与某个具体 reference 文件不因字面相近自动相同；`能力注册表` 与具体 registry 路径也须有来源同一性证据。证据为“未知”时保留独立节点、属性或文字，不合并实体。

随后建立图形事实映射：

| 映射项 | 决策图表 | 语义图解 |
| --- | --- | --- |
| 来源 | 文件/数据对象、版本、读取时间、SHA-256 | 文件/代码/schema/访谈记录、版本、定位 |
| 原子事实 | 字段、值、单位、分母、时间窗、筛选、缺失值 | 节点、边、方向、条件、状态、顺序、职责、基数 |
| 变换 | 排序、过滤、聚合、派生公式 | 分组、折叠、跨层连接、概览/细节拆分 |
| 不变量 | 不静默改值、单位、标签、分母或排序含义 | 不补造组件、调用、状态、负责人、先后或基数 |
| 不确定性 | 缺失值与不可比维度显式保留 | 推断、假设和待确认使用独立样式并附核验动作 |

发送前数图中可见值/节点/边与映射行：逐项相等，一行一边并保留完整 source locator 和对应 P-ID，禁“同上”或汇总；内嵌草图、方案图也适用。语义图中的每个可见节点也须有独立映射行，至少记录节点 ID、图中标签/职责、source locator、同一性证据和证据状态；节点只出现在边的端点中，不等于其名称或职责已经取证。节点行与边行可放在同一张表，不强制拆成两张账本。映射已随正式文件交付时，聊天引用对应图 ID 和文件，不重复粘贴整表。失败则删图改文字或先取证。

语义图发送前做五项机械检查：`来源命题集合 = included + excluded`；`included 命题集合 = 图中边/属性 = 边映射集合`；`图中节点集合 = 节点映射集合`；每条边独占一行且有起点、关系/条件、终点和 locator；图、账本、摘要及静态降级不存在同一命题的主客体冲突。图中没有来源不存在的中介节点或边，布局分组不能伪装成业务节点。用户要求本轮出图时，不能只写“后续应拆图/保留表格”：本轮要么交付可核验的全部图与降级表/文字，要么触发停止条件并保留原表达物。

## 3. 工具真值

工具记录分开保存，不互相推导：

```text
installed | callable | call_succeeded | version | commit | license
```

- `installed=true` 只证明本地存在；当前会话暴露接口后才可写 `callable=true`。
- 只有本轮最小调用返回目标结果，才写 `call_succeeded=true`，并附探测时间和证据路径。
- 模板中的三个状态默认为 `null`（unknown）；没有同名可调用接口或独立探针证据时保持 unknown，不能用“本地可手写 SVG”等降级能力冒充工具调用成功。
- 身份或许可证不明、用途不适用、调用失败时，降级为 Mermaid、本地 HTML/SVG、表格或文字；不得写“已使用”。
- diagram-design 是 MIT 可选 pilot；缓存身份与当前可调用性必须每轮分开探测。Lieflat 的非商业许可边界见 `references/chart-delivery.md`。

## 4. 按载体交付

先锁定用途、目标文件类型与可编辑范围；已有视觉方向直接延续，不因改载体重开方案。事实映射、来源、工具真值与保真规则共用，文件及验证按载体适用，不擅自增加用户未要求的网页或预览项目。

| 载体 | 交付与验证 |
| --- | --- |
| HTML | 自包含可编辑 HTML、SVG/PNG、manifest、双视口截图、浏览器及离线结果、替代文本与静态回退 |
| PPTX | 可编辑演示稿；核对文字/形状的编辑范围、页面顺序、渲染可读性和事实一致性；不要求 HTML 或窄屏 |
| drawio | 可编辑源文件；核对节点、方向、条件、责任、异常和实际渲染；网页预览仅在另有要求时交付 |
| SVG/PNG | 目标图像与事实映射；核对标签、单位、语义和实际渲染；要求可编辑时不能只交位图 |

验证记录优先复用项目现有记录。使用 manifest 时采用 `templates/visual-manifest-template.json`：`delivery_format` 为 `html / pptx / drawio / svg / png`，旧文件缺省为 `html`；每个载体独立登记，不把混合交付压成一个通过状态。非 HTML 使用 `files.<格式>` 和 `files.render_evidence` 及各自 `sha256`；`artifact_verification` 记录布尔值 `readable`、`editable_required`、`editable` 与 `editability_scope`。PPTX/drawio 须可编辑；PNG 不能冒充可编辑源。非网页不填写浏览器结果。manifest 自检只检查记录与文件身份，不代替真实打开、渲染或编辑检查。

缺少承重验证时标“草稿/部分通过”，不能写“正式交付完成”；工具缺口如实保留，不能补造截图。重绘额外保留保真账本，可用 `templates/visual-fidelity-ledger-template.md`。产物默认进入项目约定目录，发布、上传及远端写入仍单独授权。

## 5. 语义图解规则

1. 先选语义模式，再选视觉类型：层级、流程、状态、时序、关系、比较不可混用。
2. 固定并标明阅读方向；边须有方向、条件或关系标签。仅列节点/状态不等于存在边；来源为 `A -> B -> C` 时不得折叠成 `A -> C`，主语、宾语、方向和中介逐项继承。
   `A + X/Y` 只证明并列或正交维度，不证明 `A -> X`、`X -> Y` 等迁移；来源未给边时用节点属性、注释或分层表表达。
3. 状态机保留成功、失败、取消、重试、回退和不可达边；流程图保留入口、出口、分支和责任边界。
4. ER 图保留实体、主键/关键字段、基数及未知关系；没有 schema 证据不推断字段或基数。
5. 超出复杂度预算时拆成“概览 + 细节”，不缩小到不可读，也不删除失败路径。
6. 重绘 Mermaid、截图或旧图时逐项登记保留、变化、丢失和理由；审美改动不得改变语义。无法保留全部承重节点、边和失败路径时，原 Mermaid/旧图继续作为规范来源，停止输出替代图，只交付失败账本与补证动作。

## 6. 浏览器与可访问性验证

浏览器、双视口和离线要求仅适用于 HTML 交付；原生文件和静态图按上一节验证。非颜色唯一编码和可读标签适用于所有载体。

- 至少验证一个桌面和一个窄屏视口：无裁切、重叠、横向溢出，文字和连线可读。
- 控制台、页面和资源错误为 0；外部资源为 0，或明确来源、许可及离线行为。
- 断网后仍能看到核心内容与静态回退；“页面能打开”不等于事实保真通过。
- 颜色不能是唯一状态编码；关键节点/值有文本标签，SVG/PNG 有用途明确的替代文本。

## 7. 停止条件

- 关键值、节点、边、方向、状态或基数存在未解释差异；
- 图形制造不存在的精度、因果、完整性或统一总分；
- 工具身份、许可、来源或调用状态无法证明；
- 图比表格/文字更难核验，或只改善美观；
- 无法完成事实映射或该载体实际需要的渲染、编辑与可访问性检查；HTML 另含双视口、离线与静态回退。

触发停止条件时保留原表达物和失败证据，回到当前入口补证；不得用视觉润色抵消正确性缺口。
