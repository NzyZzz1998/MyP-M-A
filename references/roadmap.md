# 路线图与优先级工作流

当用户需要判断多版本规划、跨阶段路线图、很多候选需求的全局优先级时，使用路线图工作流。

如果用户正在写单个版本的 PRD，优先级与版本范围应放在 `/prd` 前半段完成，而不是单独启动路线图工作流。`/roadmap` 更适合回答“未来几个版本怎么排”“这一堆需求如何分批”“哪些方向暂时不做”。

## 输出结构

### 1. 当前阶段判断

判断产品处在探索、验证、打磨、增长、稳定维护中的哪个阶段。不同阶段不应该使用同一套优先级标准。

### 2. 候选事项整理

把需求按主题归类，例如：

- 核心体验
- 稳定性
- 用户反馈
- 收入或增长
- 技术债
- 体验精修

### 3. 优先级判断

每个事项从四个角度判断：

- 用户价值
- 当前紧迫性
- 实现成本
- 风险降低效果

### 4. 推荐路线图

按版本或阶段输出：

- 现在就做
- 下一版做
- 验证后再做
- 暂时不做

### 5. 取舍说明

说明为什么某些看起来有吸引力的需求不应该现在做。

## 写作要求

- 不要把所有需求都排进路线图。
- 对个人项目，要优先考虑可完成性和反馈速度。
- 如果用户正在做 UI 打磨，不要过早引入大功能。
