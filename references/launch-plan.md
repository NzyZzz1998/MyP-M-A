# 发布计划工作流（已并入 /acceptance）

发布计划不再作为独立入口优先使用。用户使用 `/launch` 或要求“上线、灰度、回滚、发布说明”时，按 `/acceptance` 处理，并读取 `references/acceptance.md`。

发布不是独立规划入口，而是验收与风险控制的一部分。发布检查、回滚方式、发布说明和上线后观察应与验收标准、日志/埋点、人工测试和回归范围一起输出。

当功能接近完成，需要上线、灰度、回滚、通知用户或整理版本说明时，使用发布计划工作流。

## 输出结构

### 1. 发布目标

说明这次发布希望带来什么变化，以及主要面向哪些用户。

### 2. 发布范围

- 新增内容
- 修复内容
- 不包含内容
- 已知限制

### 3. 上线前检查

列出必须确认的项目：

- 功能验收
- 回归测试
- 配置检查
- 日志或监控
- 回滚方式
- 用户数据兼容

### 4. 灰度与回滚

说明是否需要灰度、如何观察异常、什么条件下回滚。

### 5. 对外说明

给出用户能看懂的更新说明，避免内部术语。

### 6. 上线后观察

列出上线后 24 小时、3 天或一周内要看的信号。

## 写作要求

- 对个人桌面应用也要保留最小发布检查。
- 不要把发布计划写成营销稿。
- 如果功能风险高，优先补回滚和日志。
