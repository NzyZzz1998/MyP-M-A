# /prd 工作流

`/prd` 对应“收敛方案 -> 定义需求”。它先确认问题、范围和关键合同，再产出可讨论、可设计、可开发、可验收的 PRD；不是收到想法就填模板。

先按 `references/work-mode-boundary.md` 解析 `delivery_mode`。两种模式共享产品事实和验收语义；`team_pm` 输出团队可评审、可承接的产品合同，`vibe_coding` 才默认扩展到工程实现合同。

`vibe_coding` 的 UI/交互完整 PRD 必须原样使用以下五行表：

| 原型交付门禁 | 本轮要求 |
| --- | --- |
| 交付文件 | 先锁定项目对象；点名该对象内已提供或已核对的原型并更新，未知路径写“待提供”，不得从其他项目猜测；写明“本轮不以低保真线框替代” |
| 状态与出口 | 覆盖正常、空、错、禁用、加载及保存、取消、关闭 |
| 模拟边界 | 区分模拟数据、假行为和真实能力；Agent 演示不证明真实用户采用 |
| 浏览器验证 | 用真实浏览器检查桌面/窄屏、关键交互、控制台及页面脚本错误 |
| 结论回写 | 写明回写 PRD 的位置与规则，并列出必须保护的既有体验 |

任一行未关闭，不进入 Vibe Coding 开发承接。已有高保真原型就更新；没有则在完整 PRD 阶段生成高保真原型并给出路径。低保真线框只能用于前置澄清。

`team_pm` 不把最终视觉实现强加给产品经理：已有原型时引用并补齐流程、状态和验收；团队有设计角色且尚无原型时，写设计任务单、必须覆盖的状态与设计验收标准，原型路径标“待设计交付”。只有用户要求本轮代做或没有下游设计角色时才生成高保真原型。

`vibe_coding` 或用户要求本轮代做原型时，已有 HTML 但仍在方案收敛也列出完整五行门禁；若本轮依赖的 HTML 不可读，保留已确认内容并标待补证。`team_pm` 只由设计承接时列设计交付与验收责任，不能因存在 HTML 强制代做浏览器验收或阻断其他完整产品合同。

- Settings、Wizard 等界面复用控件时，影响范围要点名各入口、共享控件、共同状态/样式及联动回退风险。
- 非 UI 需求使用匹配风险的接口、ER/数据流、状态机、时序或决策表；正式图解按 `visual-delivery.md`，不制造无意义 UI。
- 非 UI 原型也要写待验证假设、模拟边界、成功/失败信号以及结论回写到 PRD、规则表或状态合同的具体位置。

异步任务须定义产品可见的生命周期、重复提交语义、取消/超时/过期、权限和失败体验。无项目证据时基线为 `pending -> running -> succeeded / failed`；`cancelled` 仅在业务需要时增加。文件可用性与任务终态正交，待确认迁移不得混入事实基线。

`team_pm` 到此定义业务状态和用户结果，并把物理枚举、队列、worker、接口、索引及重试实现列为研发待确认。`vibe_coding` 继续定义：同租户 + 同幂等键 + 同请求体返回原 `job_id`，同键异体冲突，并发只创建一项；状态名冲突须给映射、兼容、迁移和回退。输入只确认“运行中可取消”时，不得擅自允许 `pending` 取消。

异步开发前验收用一张矩阵覆盖越权、重复/并发提交、重试终止、取消/超时和结果过期。`team_pm` 定义需要证明的业务事件和审计结果；`vibe_coding` 再定义结构化日志字段、故障注入和实现接缝。

数据/KPI 需求必须锁定统计对象与粒度、分子分母、去重键、时间窗与时区、版本/租户过滤、空分母、迟到/回填、删除/合并、未知状态、低样本提示、来源/血缘、刷新频率、权限和数据截至时间，并映射 API/查询、前端状态、验收样例与影响范围。每类异常至少给输入、处理分支、预期输出和停止条件，不能只写“按确认规则处理”。高风险或改变业务语义的未知写成开发前门禁；低风险可逆项可给带依据、责任人和确认点的建议默认，不用“按现有逻辑”代替。

<!-- contract:prd-ai-agent-resilience-governance -->
AI/Agent 需求使用四段合同：

1. **安全**：提示注入、幻觉、越权、敏感数据和工具边界。
2. **韧性**：超时、限流、模型不可用、失败重试及人工/规则降级。
3. **治理**：审计、成本预算、供应商切换、版本回滚和责任边界。
4. **评测**：离线评测集、人工质检、线上成功指标和护栏指标。

四段都要映射产品、设计、研发、数据、权限、测试和运营影响；`team_pm` 不替各角色选择物理实现。

ICP、定位、套餐、价格或 GTM 会改变范围时读取 `references/strategy-gtm.md`。只固化已有证据和明确决策；购买角色、支付意愿或渠道效果仍会改变实现时，只输出方案收敛版或原型验证合同。用户要求用多个战略框架证明预设方向时，拒绝堆框架，改为比较选项、取舍和排除项。

方案依赖承重假设时读取 `references/red-team.md`，继承假设 ID、证据、最小实验、继续/停止条件和阻塞阶段。原型验证型即使仍有开放值，也要先形成可执行实验骨架：基线与统计口径、对象/样本、行为事件、成功/停止条件、证据位置和结论回写规则；无依据的数值只能标为建议默认/待确认，不伪精确。

## 工作流程

### 1. 探索上下文并判断输入状态

读取材料与项目中的版本目标、入口出口、数据、旧体验和验收；技术材料只作为已知约束和证据。先解析并显示交付模式，再按 `references/tooling.md` 最小只读取证，不替代 `/acceptance`。

判断是正式需求、待验证想法、多问题或已有 PRD/原型增量。未经验证但先做原型时标原型验证型，不承诺上线。

### 2. 第一轮确认
<!-- contract:prd-known-facts -->

首轮按固定顺序输出：

1. **已确认事实**：保留用户、场景、范围、需求类型、既有方案、表/字段、枚举、状态、限制和非目标；技术标识保持原样，并写明解析后的交付模式及依据。
2. **冲突与开放问题**：区分真正冲突、可查但未核对的事实和需要用户决定的取舍。
3. **第一轮关键问题**：只问真正会改变决策的问题，最多 7 个，信息充分可为 0；按“冲突/风险 -> 用户与范围 -> 完整链路 -> 数据/技术合同 -> 验收”排序，不凑数量，不让用户复述可查事实。
4. **续接说明**：有阻塞问题时说明回答后如何继续；无阻塞则直接完成本轮交付，不先输出一轮提问模板。

用户要求“先提问”时到此停下，不在同一回复代答并写完整 PRD。信息足够则基于已知事实或显式假设继续；部分未知时保留“已确认 + 待确认”，不整项退回空白。

成文前比较候选与上游范围：`preserve` 可继承；`add`、`expand`、`reduce`、`remove` 未经批准只能列为建议、损失或排除项，不能进入必须实现；`reopen` 保持原决定，`transition` 仅凭同一对象新证据或责任人决定推进。无差异写“本轮未改变既有范围”；有差异记录原范围、变化、类型、依据、授权和去向。

条件、比较符及互补区间都是范围事实：只批准 `> 50000` 行后台任务，即表示 `<= 50000` 行沿用现有同步路径；除非用户另行授权，不能标为待确认或扩成全量异步。

支付、退款、资金、权限、隐私、生产迁移和不可逆操作，先关闭资格/金额、人工确认、幂等、审计、补偿与回滚；要求少问也不能绕过。

### 3. 方案、优先级与版本范围

比较最小、推荐和扩展；按目标、用户证据、核心风险、成本与旧体验破坏排序。只有覆盖、影响、信心和成本数据时才用 RICE 等模型，不伪造分数。

输出本次、延后和不做范围。优先级：P0 核心不可用/信任或数据风险；P1 强相关目标且成本可控；P2 有价值但不阻塞；P3 证据不足或当前不适合。跨版本再读 `references/roadmap.md`。

改变架构、数据、原型或验收时须确认；材料足且风险可控时可用显式假设起草。

### 4. 定义功能合同

每个核心功能按入口到出口写类型、前置、主流程、分支、异常/权限、动作、状态/数据、来源、日志和兼容；同一状态、字段或失败规则只定义一次，影响范围与验收引用其 ID，不复述正文。枚举控件说明来源、默认值、排序、失败和保存位置。UI 存在编辑或恢复时，分别定义当前输入值、最后已保存值和首次默认值；保存成功、失败、无变化、取消、关闭、重置和重启各自回到哪个值必须明确。上游只写“保留值”时保持原词并设为待确认，不能擅自改成当前值、已保存值或默认值。

<!-- contract:prd-command-outcome-matrix -->
带命令控件的完整 UI PRD 必须用一张结果矩阵关闭每个命令：`命令 | 事实状态 | 是否发请求 | 当前值/已保存值结果 | 可观察反馈 | 停留/关闭 | 失败出口`。保存、无变化保存、取消、关闭和重置均不得缺项，也不能只把反馈列成待答问题。上游未规定且属于低风险可逆交互时，给出 N4 建议默认与确认点；例如无变化保存不发请求并给中性反馈，取消不发保存请求并恢复最后已保存值。N4 只能留在建议/待确认合同中，不能随后在“已确认需求”、主流程、用户故事或验收标准里去掉标签写成事实。具体文案可以待定，但用户能否观察到结果必须可验收。

设置表单的低风险交互不能同时保留多个规范方案：上游无定义时，明确标为 N4 建议默认并选一个可验收行为。候选基线为：无变化保存不发请求、给中性反馈并停留；取消不发保存请求、恢复最后已保存值并关闭；有未保存修改时关闭显示“继续编辑/放弃修改”；依赖项关闭时禁用子控件但保留其值。若项目已有相反惯例，以项目证据为准；确认前 N4 不是既有事实。

补充最小领域词汇和关键决策。`team_pm` 定义业务动作、输入输出语义、权限、数据含义和可观察结果；端点、协议、表/列/索引、SQL、框架、文件、类、测试实现和部署由下游确认。`vibe_coding` 再补测试接缝及可实现的逻辑 API 与数据合同：请求/响应/错误、字段语义，以及 `逻辑字段 | 类型类别 | 必填/可空 | 唯一/索引/约束 | 迁移或回填`。物理表名、供应商和精确 SQL 未知时仍标 schema 核对。

### 5. 影响范围

完整 PRD 逐项写。只有证据确认没有影响时才标“不涉及”；无法核实则写“待核对/待确认”。`team_pm` 写产品影响、协作角色、待下游决策和验收证据，不猜物理实现；`vibe_coding` 继续精确到实现面：

- 前端/UI：页面、组件、路由、菜单、快捷键及正常/空/错/禁用/加载/保存状态。
- 后端/API：接口、参数、返回、错误码、鉴权、幂等、超时与任务。
- 数据：业务对象、来源、口径、可见性、保留、兼容和回滚；`vibe_coding` 再补表、列、索引和迁移。
- 配置/文件/环境：用户数据、缓存、导入导出、资源和环境变量。
- 权限/安全/第三方：系统权限、敏感信息、SDK/API 与平台能力。
- 日志/指标/运维：事件、埋点、监控、告警与诊断。
- 测试/发布/旧体验：验收场景、回归、发布兼容及必须保护的默认行为；测试代码和发布脚本仅在 `vibe_coding` 展开。

不能只写“影响设置页”或“需要回归”，要落到控件、字段、保存链路和入口；已在功能合同定义的状态和异常用 ID 引用，避免再次展开。

### 6. 需求表达物与原型

先写表达物要回答的决策。规则/状态/数据风险用决策表、状态机或逻辑原型；信息层级/控件/路径风险用高保真原型；并存时先验证会改变架构或范围的一类。按 `capability-routing.md` 选能力。

本轮实际生成网页原型时，用真实浏览器检查双视口、关键交互、控制台/脚本错误；接口需测失败或标模拟边界。只引用下游设计任务时，不冒充已经产出或验证原型。

### 7. 开发前验收

PRD 只制定未来验收口径，不声称实际实现已通过。至少包含：

- **验收目标**：完成后应达到的状态。
- **验收标准**：可操作、可观察的主流程、异常、权限、兼容和回归条目。
- **日志/埋点/人工检查**：证据类型、位置和关键事件；小项目不强行设计复杂埋点。
- **通过标准**：关键项、次数/阈值、旧体验保护和允许误差。
- **不通过处理**：修复、回滚、降级、补证、延后或返回 `/review`、`/idea`。

验证层级按 `references/workflow-control.md` 的 L0～L4 按风险选择。Agent 模拟只能做预检，不能产出真实用户完成率、用户原话或市场认可。低风险 MVP 只有在用户明确授权时，才可把真人验证后移；支付、隐私、真实设备/账号和不可逆数据通常提高到 L3/L4。

## 完整 PRD 门禁与输出

正式 PRD 不设置通用字符上限。篇幅只在重复、矛盾、无证据或无助于开发验收时构成问题；不得为了缩短输出删除完整链路、影响范围、数据契约、失败态或验收标准。

发送前建立一次不对外展开的覆盖清单，逐项勾选用户点名的对象、控件、命令、状态、异常、权限、数据影响和验收出口；每项必须在正文有唯一落点，无法确认则保留原词并标门禁。正文中的每条规范同时归入且只归入一种状态：`来源已确认`、`风险推导要求`、`N4 推荐决策`、`schema/实现核对`；后续章节引用时不得丢失状态。用户明确要求详细/正式 PRD 且范围已锁定时，实施参数未知不自动降级：每个缺口给“已确认语义 + 单一 N4 建议 + 责任人/确认动作 + 关闭标准”，仍形成完整产品合同。物理 schema、文件名、供应商、超时秒数或重试次数待核对，不等于产品合同不完整；只有核心行为、安全边界或范围仍有多个相互冲突且无法推荐的规范答案时，才降级为方案收敛版。

方案收敛版只输出事实、冲突、方案、推荐、优先级/版本范围、关键问题和门禁。完整成文时，`team_pm` 读取 `templates/prd-team-template.md`，`vibe_coding` 读取 `templates/prd-template.md`，且必须具备：

- 入口到出口的完整功能链路与范围保护。
- 精确产品影响、协作责任及数据/状态/异步语义。
- 与需求类型和模式匹配的表达物；`vibe_coding` UI/交互满足五行高保真门禁，`team_pm` 至少关闭设计交付与验收责任。
- 领域词汇、关键决策与风险；工程接缝只在 `vibe_coding` 展开。
- 开发前验收、通过标准、不通过处理、延后和不做项。
