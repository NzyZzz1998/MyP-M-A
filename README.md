# MyP-M-A

**把产品评审、价值判断、需求定义与真实验收，串成一条可追溯的中文工作流。**

`v0.36.0 Stable（已同步远端）` · `v0.35.0 历史回退基线` · `中文优先` · `5 个入口`

MyP-M-A（My Product Manager Assistant）是面向 Codex 的个人产品经理 Skill。你可以直接给它项目路径、产品想法、PRD、截图、日志或构建产物；它会先判断当前阶段，再交付该阶段真正需要的成果。

它不是一套 PRD 模板，也不会把每个输入都升级成需求。它更关注三个问题：**现在要做什么判断、已有证据能支持什么、下一步怎样最小而可靠地推进。**

## 一条完整的产品闭环

```text
项目 / 页面 / 反馈 / 想法 / PRD / 构建产物
                     ↓
                自动判断入口
                     ↓
 /review  →  /idea  →  /prd  →  开发承接  →  /acceptance
    建图       判价值      定需求      计划与进度       验证与发布
                                  ↘ /prompt：压缩下一步交接
```

| 入口 | 解决的核心问题 | 典型交付物 |
| --- | --- | --- |
| `/review` | 项目现在是什么样，问题在哪里 | 产品/工程地图、证据化发现、影响与分流 |
| `/idea` | 这是真问题吗，值得现在做吗 | 固定字段需求池、证据等级、压力测试、最小实验 |
| `/prd` | 应该做成什么，怎样避免遗漏 | 完整需求、影响范围、数据/状态合同、原型、开发前验收 |
| `/acceptance` | 实际实现是否达到发布标准 | 产物身份、真实证据、缺口、人工验证、发布结论 |
| `/prompt` | 下一轮怎样交接得短而完整 | 带范围、证据、授权、停止条件的可执行提示词 |

`/prompt` 是辅助入口，不改变四个产品阶段。没有显式命令时，MyP-M-A 会根据用户要解决的决策和已有产物自动路由。

## 30 秒开始

将仓库放到支持本地 Skill 的 Codex 目录中，并保证入口文件位于：

```text
<CODEX_HOME>/.agents/skills/mypm/SKILL.md
```

重新加载 Codex 后，选择 `MyP-M-A`，或在对话里直接点名 `$mypm`。最简单的用法不需要记命令：

```text
使用 $mypm 深度评审当前项目，先建立产品和工程地图，再告诉我最值得解决的问题。
```

也可以显式指定入口：

```text
/idea 我想增加团队共享能力。请判断它是不是真需求、证据是否足够、现在该不该做。
```

```text
/prd 基于已经确认的需求写完整 PRD。只追问会改变目标、范围或核心合同的问题。
```

```text
/acceptance 锁定当前构建产物，基于日志、截图、测试和人工补证判断是否可发布。
```

## 它真正交付什么

### 先判断阶段，再写文档

Review 只负责建立地图和发现问题；Idea 负责判断价值；方案收敛版不冒充完整 PRD；测试计划也不冒充真实验收。每个阶段只交付当前最小充分成果。

### PRD 能直接承接开发

完整 PRD 会覆盖入口到出口、前后端与数据库影响、状态和失败链路、保存/取消/关闭等交互、日志与验收口径。涉及 UI 时，已有高保真原型必须更新；没有原型时，在正式 PRD 完成阶段补齐。

PRD 经确认后，可以继续生成：

- `dev_plan_vx.x.md`：实施顺序、影响文件、风险与回退。
- `progress_vx.x.md`：最小可执行任务与状态看板。
- `dev_log_vx.x.md`：按需记录开发过程，不与进度看板混写。

### 验收只认真实证据

Acceptance 会锁定分支、HEAD、候选产物、哈希、环境和证据时间。自动测试、日志、截图、GUI 操作和人工补证分别记录；无法执行的路径保持“待验证”，验收通过也不等于已经授权提交、推送、打 Tag 或发布。

## 判断原则

- **证据先于结论**：区分事实、推断、假设、决策、风险和开放问题。
- **未知就保持未知**：没有数据时给采集或实验方案，不编造用户、阈值、接口、字段或完成状态。
- **范围必须可追踪**：正式交付物引用上游需求、版本、文件和证据，并写清非目标与回退。
- **外部能力只做增强**：浏览器、Computer Use、数据库、代码扫描和 GitHub 等工具按需调用；不可用时降级，不伪装成功。
- **仓库是事实源**：Basic Memory 只帮助跨线程恢复和收尾，不能覆盖项目中的 PRD、进度、验收与发布事实。

Basic Memory 支持 `auto`、`suggest`、`off` 三种模式。默认只在已知项目的新线程上下文不足时恢复，在稳定阶段结束时去重更新。

## 可校验的能力层

v0.36 在五个入口之下增加离线治理的能力注册表。首批 Discovery 问题验证、产品数据分析、Strategy/GTM 决策三张能力卡保持 `pilot`：它们声明何时适用、何时不适用、需要什么输入、交付什么结果以及证据和降级边界，方法正文仍由既有 reference 负责。

能力卡不进入默认常驻上下文，也不是新的用户入口。注册表缺失时，v0.35 的五入口工作流仍可回退运行；只有命中对应场景时才按需装配。

同一治理层还提供：

- 12 条中性外部同题 benchmark，用分维结果比较代表性 PM Skills，不生成掩盖关键失败的统一总分。
- 公开案例准入合同，检查授权、隐私、artifact 哈希、证据定位和撤回生命周期。
- 完全合成的 withdrawn dry-run，用于证明机制可执行，不冒充真实用户研究或公开案例。

## 本地校验

在仓库根目录运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\validate-skill.ps1 -Strict
```

该命令检查 UTF-8、常见乱码、版本一致性、运行时引用、评测 schema、生命周期归属、本地 Markdown 链接和孤立资源。静态校验不能替代模型行为评测。

## 仓库结构

```text
mypm/
├─ SKILL.md       # 入口路由与常驻核心合同
├─ capabilities/  # 离线注册表与按需能力卡
├─ references/    # 按当前入口渐进加载的规则
├─ templates/     # PRD、验收、计划等正式模板
├─ evals/         # 稳定、挑战、触发与文件型用例
├─ examples/      # 公开案例准入规范与合成 dry-run
├─ scripts/       # 静态校验与评测治理工具
├─ notes/         # 路线图、评测历史与版本事实源
└─ agents/        # Codex 展示与默认提示配置
```
