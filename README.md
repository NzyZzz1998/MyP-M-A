# MyP-M-A

**把想法写成完整需求，把项目事实接续下去，把交付结论落到证据上。**

面向团队协作与 Vibe Coding 的中文产品经理 Skill，运行在 Codex、Claude Code 等 Agent 宿主中。不是独立应用，不自带模型，也不要求先装齐一套插件。

> **当前版本：v0.43 Candidate · test 分支。** 本版包含可选项目记忆、独立诊断日志、专项路由、双方法代码审查适配和受控依赖补装。维护者已接受已知问题，技术结论仍为部分通过；不是新 Stable。原 v0.42.0 留在 main / 既有 tag 作为稳定基线。

| 你的任务 | MyP-M-A 的交付 | 可阅读示例 |

## v0.43 解决什么问题

这一版把长期维护与专项协作接进主流程，保留“从零写好 PRD”的核心能力。五个入口不变，不引入另一套总控或平行需求系统。

| 以往容易出现的问题 | 本版的处理 | 仍需知道的边界 |
| --- | --- | --- |
| 换线程后重复解释项目，稳定决策丢失 | 项目 Memory：按授权恢复、稳定收尾写回、回读核对 | 默认关闭；仓库优先，不保证所有宿主自动触发 |
| Skill 用得不好，却没有可追踪的改进记录 | 独立本地诊断：入口、纠正、返工、交付和工具问题 | 不存聊天全文，不上传遥测，不把日志混进 RAG |
| 有很多专项 Skill，却不知道何时用哪一个 | 按问题、对象、能力与授权选路，避免重复执行和嵌套循环 | 注册、安装、可调用、实际执行与通过验收分开 |
| 代码审查漏掉未提交文件，或同一方法重复跑 | code-review 与 open-code-review-delegate 同快照适配，覆盖 Git 四层并记录跳过原因 | 已验证双方法，不冒称隔离双模型 |
| 更新后缺依赖，手工补装易漏或覆盖原配置 | 授权后检查固定清单，只补缺失的领域建模与问卷试点 Skill | 默认关闭；不装 CLI、不配凭据、不覆盖已有 Skill |
| 回归结果混在一起，修复是否有效难判断 | 输入/快照/评分可追踪，稳定、挑战、专项与质量观察分账 | 单轮高分不是普遍领先，未验证不改成通过 |

版本由原“0.42 维护候选”明确为 **0.43**，不是为了命名再开启一轮功能开发。命名前的候选已完成双模型全量；下文如实说明其冻结身份与继承边界。详见[版本身份与收口](notes/v0.43-candidate-identity.md)。

## 开始使用

### 安装本页对应的 test 版本

以下为 PowerShell 个人级安装，**选择自己的宿主运行一条**：

```powershell
# Codex
git clone --branch test https://github.com/NzyZzz1998/MyP-M-A.git "$HOME\.agents\skills\mypm"

# Claude Code
git clone --branch test https://github.com/NzyZzz1998/MyP-M-A.git "$HOME\.claude\skills\mypm"
```

已有安装先查看分支、commit 和本地修改，再选择更新；不要覆盖目录或强制重置。只需要已发布稳定版时选择 main 或明确的稳定 tag，不会获得本页全部增量。自定义与项目级目录按宿主实际扫描规则设置：[Codex](https://developers.openai.com/codex/skills/)、[Claude Code](https://code.claude.com/docs/en/skills)。

### 发出第一条任务

让宿主加载 Skill 后，将以下文本发给 Agent，不是在终端执行：

```text
mypm /review

评审当前项目，先说明用户、核心流程、模块关系和当前进度，
再列出有证据的问题与下一步。本轮只读，不修改代码。
```

不记入口也可以说“用 MyP-M-A 帮我判断这个想法”。先给项目路径或相关材料，不要求每次从头走五个阶段。

### 选择交付方式

| | 团队协作型 team_pm | 全流程型 vibe_coding |
| --- | --- | --- |
| 使用场景 | 与设计、研发、测试协作 | 自己用 Agent 继续做产品 |
| 共同要求 | 完整业务流程、规则、状态、权限、异常、指标与验收 | 同样完整，不以精炼删除必要内容 |
| 职责深度 | 不替研发决定无依据的物理实现；原型可交设计承接 | 经确认补齐高保真原型、工程约束和开发承接 |
| 停止位置 | 产品评审与角色交接点 | 按用户授权推进，不跳过确认或发布授权 |

默认 auto：组织协作或意图不明按 team_pm；明确要求同一 Agent 继续实现、测试或发布承接时才进入 vibe_coding。显式指定优先，两种模式不能改变已有事实、数字或验收标准。

```text
mypm /prd
delivery_mode=team_pm

依据当前材料形成供设计、研发和测试评审的完整 PRD。
覆盖主流程、业务规则、异常、旧体验保护和验收。
不替研发决定物理实现，本轮停在 PRD 确认点。
```

自己做产品时可改为 delivery_mode=vibe_coding，明确原型与后续实现范围；确认后再承接开发计划、进度和开发日志，不能只改一个模式字段就获得提交或发布授权。

## 五个入口，共用一份事实

| 入口 | 当前要回答的问题 | 交付与边界 |
| --- | --- | --- |
| /review | 现在是什么样，问题在哪里？ | 建立项目地图并核证发现，不直接升级为确认需求 |
| /idea | 是真问题吗，值得现在做吗？ | 判断证据、价值与最小实验，不用分数替代事实 |
| /prd | 应做成什么，怎样避免遗漏？ | 完整定义范围、流程、状态、业务与验收，不猜实现 |
| /acceptance | 实际交付达到标准了吗？ | 对照产物和真实证据；计划、模拟文字不当实测 |
| /prompt | 怎样交给下一轮继续？ | 压缩交接，保留事实、授权、限制和停止条件 |

/prompt 是辅助交接入口，不是第五个产品阶段；上述命令由 Skill 解释，不保证每个宿主都有同名菜单。

## 专项路由如何工作

MyP-M-A 管目标、范围、事实、授权与验收；专项能力只补当前缺口。流程为：**确定问题与对象 → 探测能力 → 核对授权 → 最小调用 → 将证据写回同一份交付物**。

### 本版明确接通的四项提供者

| 提供者 | 何时使用 | 当前接入与验证 |
| --- | --- | --- |
| domain-modeling | 术语多义、领域边界不清，且用户明确选择 | 固定来源文件适配；合成小样本已验证，未冒称原生自动加载 |
| to-questionnaire | 把缺失业务信息变成可填写的问卷，且用户明确选择 | 固定来源文件适配；复用已有答案，只生成、不代发 |
| code-review | 用户明确选择该技能的两轴审查方法 | 本地方法适配；沿用现有规格，规格缺失只跳过规格检查 |
| open-code-review-delegate | 代码评审中的默认扫描提供者 | 真实本地 CLI 链路已测；加载规则后由当前宿主完成判断，不自带独立评审模型 |

缺失工具时仅降级受影响步骤，如实说明哪项未执行，不阻塞独立能力。没有把 implement、triage、wayfinder 等整套总控接进来。上表使用技能名，实际采用本项目登记的适配器，不等于调用宿主中任意同名工具；来源、许可证、固定版本与逐项状态见[注册表](capabilities/provider-registry.json)与[接入矩阵](notes/external-skill-routing-review-20261017.md)。

### 已有能力继续按需使用

| 任务 | 路由方向 | 使用条件 |
| --- | --- | --- |
| 数据质量、指标、KPI、市场规模 | data-analytics 对应能力 | 有数据与口径；缺资料时先补证，不制造计算结果 |
| 访谈、JTBD、机会树、战略/GTM | 仓库内 Discovery / Strategy reference | 选择能回答当前决策的最少方法，不叠框架 |
| 原型、网页、桌面验收 | 已有设计系统、Figma/UI、浏览器、Computer Use | 按交付模式和宿主真实能力；文字不能冒充截图 |
| 数值图表与语义图解 | 按数据/关系分流；diagram-design、Lieflat 可选 | 来源逐值/逐边核对；Lieflat 非商业限制保留 |
| 工程实施、TDD、排障 | 沿用项目选定的方法，例如 Superpowers | 已有实现授权才执行，同类流程不重复编排 |

这张表不是“一键安装清单”，更不意味着所有宿主都已实测。工具实际可用性与来源见[能力路由](references/capability-routing.md)、[专项适配合同](references/external-provider-routing.md)。

### 双方法代码审查

冻结同一快照，覆盖已提交、暂存、未暂存和未跟踪改动，逐文件记录覆盖/跳过原因；不强制先提交。双审串行保留各自报告，再核证、去重、解释分歧。审后改代码，相关旧证据失效。

组合为 **code-review + open-code-review-delegate**。本机已测其底层 OCR CLI v1.13.1 与同上下文双方法 dual-method；**这不是两个独立模型的盲审**。dual-isolated 要另有 reviewer 预算和真实隔离证据。默认子 Agent 预算为 0，无发现不等于测试、产品验收或发布通过。

```text
mypm /review
审查当前未提交代码，使用 code-review + open-code-review-delegate 同快照双方法。
覆盖暂存、未暂存及未跟踪文件，保留两份报告及核证结论。
不提交、不推送、不外发、不派子 Agent；依赖缺失明确说明。
```

证据：[代码双审修复](notes/real-code-dual-review-20261018.md)、[真实 OCR 链路](notes/ocr-live-verification-20261018.md)。

### 更新后缺 Skill 怎么办

可选补装默认关闭。首次明确授权后，升级首次使用只检查固定清单中缺失的 domain-modeling 与 to-questionnaire 试点适配；不覆盖已有 Skill、不追随任意上游更新、不安装 OCR/宿主插件、不配置凭据、不顺带开启 Memory 或日志。新增来源或包变化重新确认。不是后台自动更新服务，具体操作见[依赖授权与补装](references/provider-dependencies.md)。

## 项目记忆与诊断日志

| | 项目 Memory | Skill 诊断日志 |
| --- | --- | --- |
| 目的 | 长期维护具体项目，跨线程续接 | 找到 MyP-M-A 的误用、返工和改进机会 |
| 内容 | 稳定决策、范围、状态、来源与限制 | 入口、纠正、返工、交付及工具问题的结构化事件 |
| 使用方式 | 授权后按需恢复，稳定收尾保存并回读 | 独立授权后本地记录，不进入 RAG |
| 默认与成本 | off；auto / suggest / off；可能增加上下文与 Token | off；不启动额外模型，不保存对话全文或上传遥测 |

两者分别授权，一项开启不代表另一项开启。项目仓库始终是事实源，记忆不能覆盖当前需求或跨项目补事实；默认只操作绑定的项目笔记。配置位于项目 .mypm.local.json，数据在仓库外，本机授权不随开源仓库传播。

日志写 SQLite 后关闭连接；Memory 使用一次性 CLI，并释放本次自有进程。不按进程名批量杀服务，也不能承诺回收宿主 MCP 或 Codex 本体全部内存。

当前本机 CLI/桌面新会话恢复已有证据；一次免提醒收尾初测漏记，修复后一个新会话成功写回、回读及记录事件。**不是长期无遗漏或全部宿主可靠性的证明。** 配置、成本、开关与限制见[本地 Memory/日志指南](references/local-memory-diagnostics.md)。

正确性、证据和完整性优先于精炼；未知保留未知。评审不等于需求确认，试验成功不等于开发授权，验收通过不自动授权提交、推送、tag、Release、生产写入或外部传输。新增风险先给有依据的建议，不能悄悄升级成硬门禁。

**不绑定模型厂商，优先适配 GPT 系列。** 当前候选完整观察覆盖 GPT-6.1 Sol medium 和 GPT-6 Astra medium，不能据此宣称其中一个普遍最好。其他型号与推理强度按实际任务验证；历史模型成绩不替代当前版本的新验证。
