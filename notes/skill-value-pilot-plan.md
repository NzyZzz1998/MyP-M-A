# Skill 增益验证：原生能力、v0.42 与轻量核心

## 决定与边界

维护者提出：模型通用能力增强后，应重新检验对 Skill 的依赖。经确认，本轮先做三组增益预检，不直接启动 v0.43，不覆盖 v0.42 Stable，不继续为旧题堆规则。

要回答的是“Skill 是否减少事实错误、关键遗漏、越界和交付返工”，而不是“是否更像 MyP-M-A 的格式”。历史版本间及外部 Skill 对标不能直接替代无 Skill 对照。

## 本轮范围

| 对象 | 处理 |
| --- | --- |
| 原生组 | 同宿主，不主动加载用户 Skill；宿主自身指令和技能目录元数据仍存在 |
| 完整组 | 固定 `v0.42.0`，提交 `15d65a90c047ac7858e0df72eed3aac57108abad`，按现有规则读取运行时快照 |

| 题面 | 10 个新编合成任务：6 个日常交付、4 个风险判断；复用风险类型，不冒充真实业务或独立留出集 |
| 执行 | 原协议继承主模型并请求 medium；运行元数据已核验为 GPT-6 Astra medium。两批各五题，三组同题同序、最多并发三名 |
| 评分 | 匿名业务检查点与四维质量分别报告，原答不可因低分重跑；重要争议保留裁决，不改原分 |

不要求专用标题、固定表格或特定图形语法；只检验用户实际要求。正确性、证据、完整性优先于篇幅，字符数与时长单列。人工返工时间和真实用户满意度本轮不测量，不能用评审建议数代替。

## 可证伪的判断

- 轻量核心若出现完整组没有的关键错误，不直接替换 Stable；定位起作用的具体规则，而不是按平均值掩盖缺陷。
- 原生组与轻量组若质量可比且附加负担更少，进入授权的真实任务试用，不直接宣称所有场景都无需 Skill。
- 只有某些任务受益时，考虑按场景加载；若附加规则无可解释增益且增加负担，优先停用该部分。
- 本轮单样本合成预检不产生统计显著性、真实生产收益或全场景替代结论。真实任务试用需维护者另行提供可使用的脱敏材料。

建议候选措辞：只对本轮实际涉及的发布对象核对适用策略；来源明确且已确认的项目要求、已核实的平台要求或适用安全约束可构成门禁。一般风险应给依据与最小补证建议，未确认的新增要求不得冒充既定产品合同。已证实的安全阻塞不能降级为可选建议。此措辞目前仅为设计稿，不能作为已安装 Skill 的覆盖指令。

### 接下来怎样验证，而不再铺开大面板

上述静态试点阶段未运行模型。随后获准按以下设计完成仓库外规则实验，结果另记于下一节：对签名策略做最小语义差量，并配四种成对场景：明确禁止、策略未知、没有安装器、已证实安全阻塞。先冻结题面和判断依据；已明确禁止的原案例保留其严格程度，未知场景不预置禁令，无关对象不扩张，安全问题不降级。

规则试验与资料导航收益分开测，不能同时换规则和输入资产后把收益全归给 Skill。资料导航试验固定模型与运行配置，两组使用同一份可访问源文档；只让一组额外看到索引，另留一组源文件已更新但索引未更新的情况，检查是否回源、是否错用旧状态。构建与维护索引时间单列，先做小样本排错，不宣称统计结论。

后续通过标准需先经确认，建议至少满足：明确政策不被放松、无关政策不被新增、已证实阻塞不被弱化、过期导航不覆盖新来源；正确性与完整性不回退。出现关键事实或权限错误时停止替换计划，保留原答；导航没有可观察收益时不要求业务项目接入。当前仍保持 v0.42 Stable，不自动扩展五入口改写或全量回归。
