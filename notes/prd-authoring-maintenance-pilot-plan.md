# PRD 成文与持续维护：增益试点方案

## 当前决定

- 状态：12轮合成对照、匿名评分和文件复核已完成；没有测出完整Skill的明确质量增益，停止本轮加规则与扩样。本文件不是正式版本PRD。
- 日期：准备于2026-09-15，执行完成于北京时间2026-09-16。稳定版本继续使用v0.42.0，不启动v0.43、不修改安装运行时。
- 用户已确认：写 PRD 是核心能力，不能为了维护效率削弱正确性、证据或完整性；维护能力应覆盖评审、修改、定稿和后续变更。
- 当前建议：先观察原生模型与现有 Skill 的实际缺口，只有出现可复核问题才设计最小补强。没有缺口就不增加规则。
- 当前事实源：本文负责本试点范围；实际结果由[评测历史](evaluation-history.md#prd-lifecycle-pilot-20260916)维护。下文方案和准备阶段的将来时按历史设计阅读，实际执行以末节及评测历史为准。

## 为什么验证这个方向

| 依据 | 能支持什么 | 不能推出什么 |
| --- | --- | --- |
| 用户明确要求保留 PRD 写作，并曾反馈产品文档过于复杂、职责边界不清 | 成文质量与工作适用性应继续作为主目标 | 尚不能证明当前版本仍存在同样频率的问题 |
| [前轮增益研究](skill-value-pilot-plan.md)未显示完整 Skill 的明确额外收益 | 需要保留无 Skill 对照，不继续只比较版本分数 | 不能证明真实多轮文档维护没有价值 |
| [PRD 规则](../references/prd.md)、[职责边界](../references/work-mode-boundary.md)、[追踪规则](../references/traceability.md)已有范围、职责和来源约束 | 优先复用现有能力，不增建另一套流程 | 规则存在不代表反复修改中稳定执行 |

方向判断为“小范围验证”，不是已证实高收益的功能立项。不做无依据的价值总分。关键反证是：原生模型可能已经足够好，新的维护规则反而增加篇幅、维护成本和误判。

## 两条能力线

### A. 从零写出完整 PRD

保留问题与用户、目标与非目标、版本范围、流程与业务规则、角色权限、主分支与异常、状态与数据语义、交互及设计责任、影响范围、验收、风险与待决事项。未知实现参数不能成为虚构技术方案的理由，也不能让已充分定义的产品需求只剩提纲。

不按章节数量、特定表格、术语密度或字符上限奖励回答。完整性按题面实际业务要求评判：该写的内容必须有落点，不适用部分不为凑模板扩张。建议必须与已确认要求分开，产品经理不代替研发拍板物理实现。

### B. 在既有 PRD 上准确修改

围绕单个工作循环观察：需求调整、评审反馈、局部措辞修改、确认前检查。检查更新是否覆盖授权范围内所有受影响段落，同时保留无关规则、原有文字与未授权文件。

“只改这一点”不是只替换一个词：同一规则在流程、权限和验收中有联动时，应识别授权范围内的全部影响。超出授权文件的影响只列建议与位置，不擅自同步。来源冲突不能只按文件修改时间或角色头衔裁决，正式决定与一般反馈必须分开。

这不是新入口，继续使用 `/prd`；已有材料理解可复用 `/review`。资料导航、连接器、图表升级及新的 Memory 机制不与本次同时实验。

## 推荐试点规模与材料

以下均为 N4 建议设计，确认前不是正式评测或发布门禁。

| 轨道 | 任务 | 输出与观察 |
| --- | --- | --- |
| W01 | 根据完整业务简报，从零编写一份团队协作型业务流程 PRD | 正常、异常、权限、状态、影响与验收是否完整，是否越出 PM 职责 |
| W02 | 根据另一份简报，从零编写一份工具型查询/导出需求 PRD | 不同产品场景下的事实、范围、数据口径和成文质量 |
| M01-T1 | 对共同起始 PRD 执行一项已确认业务变更 | 授权范围内应改内容是否齐全；无关章节与外部文件是否保留 |
| M01-T2 | 收到存在分歧的评审反馈，本轮只分析 | 保留各来源及决定状态，给出建议；磁盘文档不得被改写 |
| M01-T3 | 收到明确最终决定与少量指定文案修改授权 | 更新受影响规则，恢复正确状态，保留其他已定稿文本 |
| M01-T4 | 仅检查定稿条件，不再修改 | 核对变更、遗漏、冲突与证据；不能把“检查”当批准或发布 |

两组各执行上述内容，建议总计 12 个任务轮次：4 份独立成文结果与 8 份维护轮次结果。维护按链路逐轮交付，不把它当成 8 个独立统计样本。暂不扩张四模型、强度组合或全量稳定/挑战面板。

材料优先使用维护者明确允许的个人文档副本；当前未取得本试点指定业务文档，不主动搜索公司资料、飞书或供应商数据。若先准备合成材料，必须标为机制预检，不声称真实返工收益；其中“定稿措辞”是模拟保护区，不冒称来自真人。

成文简报应包含足够的业务事实，又不预填答案、Skill 模板或评分点。维护使用独立准备的共同基线，不将两组各自生成的 W01 当维护起点，避免初稿质量干扰修改能力。输入文件、授权范围、受保护段落和应改内容在运行前冻结；每轮任务只在该轮派发，不能提前给执行者后续最终决定。

首批以 `team_pm` 验证工作场景，不能外推 Vibe Coding 质量已被验证。未来若修改共享 PRD 正文、路由或双模式规则，需加入受影响的 Vibe Coding 旧用例控制；UI 原型门禁若适用，必须提供真实可读取原型及对应证据，不能用虚构通过填平。

## 公平对照与证据

原生组不主动加载用户 Skill 正文；现有组使用冻结的 v0.42.0。两组采用相同模型、档位、工具、来源权限和题面，建议先用 Astra medium，实际模型由运行元数据核验。宿主指令与技能目录元数据仍可能存在，不能将原生组描述为完全无系统提示的裸模型。

W01/W02 分别使用独立上下文；M01 每组在各自连续上下文与隔离文件副本中完成四轮，两组不能互相看到结果。相同简报、共同基线与授权时间线必须一致，组名、规则、未来轮次及评分点不进入匿名评审输入。

每轮保留原始消息、工具动作、前后文件字节、diff、输出与计时。记录“未修改”必须有文件比较支持，不能只信模型自述。必要工作产物与额外文件分别登记；尝试数全留，不因低分重跑或采用较高结果。运行前继承并锁定已有有效返回与长尾协议，不另立普通任务永久超时规则。

评审逐项对应源事实与原答，分别报告正确性、证据、完整性、可执行性。疑似问题写原句、来源、影响和解释空间，机械检查只验证字节及结构，不代替语义判断；评分争议保留原分与复核意见。图表历史 B-01 不属于本试点验证范围，不记为修复。

## 如何衡量收益

| 指标 | 口径 | 限制 |
| --- | --- | --- |
| 成文质量 | 每份 PRD 的四维原分，以及逐项事实错误、关键遗漏和越界 | 不合成单一总分，不以简短换完整 |
| 漏改 | 每轮授权范围内应改而未改的业务点数 / 该轮应改业务点总数 | 分母先冻结；零应改轮次写不适用 |
| 误改 | 未授权修改的业务点、受保护段落和文件分别计数 | 不把换行格式变化等同于业务事实错误 |
| 人工负担 | 真实用户活跃审核与纠正时间、澄清往返数、实际修订记录 | 无人参与时写未测，不能用模型建议数替代 |
| 运行成本 | 全部尝试的墙钟、可取得 token、输出字符 | 不把短尾耗时称为纯推理速度；重试成本不删除 |

若维护者参与匿名审核，交替安排组别展示顺序，记录先看某份带来的熟悉效应。文档准备、配置与维护辅助资产的时间也计入实际负担；仅运行更快不等于用户更省事。未完成真人观察时，结论只能是机制表现，不能声称已经减少实际返工。

## 分流与停止条件

以下为 N4 建议，依据是少量样本只适合定位具体问题，不足以证明统计优越；决策人为维护者，确认点在题面与评测协议冻结之前，确认前不是正式门禁。

| 分流 | 建议条件 | 后续动作 |
| --- | --- | --- |
| 保持现状 | 两组未出现可核实的关键缺陷，也未测得真实人工收益差异 | 停止当轮加规则，不为立版本继续抽样 |
| 最小补强候选 | 出现至少 1 项有来源反证、可定位到任务的成文或维护问题 | 先复核是否为材料、授权或量表问题，再决定是否改 Skill；单项问题不等于普遍缺陷 |
| 不合入修改 | 后续实验副本新增任一关键事实、权限或完整性回退 | 保留原答、停止替换；维护效率不能抵消成文退化 |
| 暂缓结论 | 任一预定任务没有有效交付，或人工负担没有真实记录 | 分别标未完成、未测；不能用部分高分宣布整体验证通过 |

若以后确需修改，先冻结实验副本；成文控制与维护链路都需与未变 v0.42 对照，不能用“原生 vs v0.42”的本轮结果替代“新候选 vs v0.42”的不回退证据。定向通过只支持受测范围，不自动晋升 Stable。
