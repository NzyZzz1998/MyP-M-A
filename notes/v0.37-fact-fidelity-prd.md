## 4. 背景与问题

v0.36 外部面板中，MyP-M-A 的正确性为 `38/48`、平均 `3.17/4`，低于 phuryn 的 `45/48`，与 product-on-purpose 的 `39/48` 接近。该结果不能证明 MyP-M-A 全面弱于其他 PM Skill，但逐题证据确认了两个可复现的承重缺陷：

1. EB-08 将“超过 5 万行转后台任务、现有同步路径保留”扩大为所有导出异步化。
2. EB-12 补造未提供的上一轮验收历史，并把“由产品负责人决定是否延期”改写成执行者可自行处理的状态。

移除 EB-08 和 EB-12 后，MyP-M-A 正确性为 `35/40`，介于两个外部候选之间。因此本版不追求增加更多方法，而是保护 MyP-M-A 已有的完整性、决策清晰度和可执行性，同时阻止“为了完整而改写输入”。

## 5. 目标与非目标

### 5.1 版本目标

1. 用户明确给出的对象、范围、数值、状态、历史和授权在跨阶段输出中保持不变。
2. 新增建议与既有事实明确分层；未经授权的范围变化不得进入“本次必须实现”或“已经完成”。
3. 启发式评分、计算结果、建议阈值和业务事实具有可区分的来源。
4. 删除不改变决策、证据、风险、授权或下一步的重复内容，同时保护正式 PRD、深度 Review 和发布验收的承重合同。
5. 用定向稳定性、关联任务、保护性控制和一次同协议候选面板证明行为改善。

### 5.2 非目标

- 不新增 `/review`、`/idea`、`/prd`、`/acceptance`、`/prompt` 之外的入口。
- 不新增 PM 框架、能力卡、数据库、服务或外部工具硬依赖。
- 不重写全部 reference，不建立第二套通用事实文档。
- 不用字符数下降代替正确性，也不把输出越长视为越完整。
- 不修改 EB-01～EB-12 的任务语义、fixture 或 v0.36 正式结果。
- 不默认执行所有模型、强度、稳定集和挑战集的穷举回归。
- 不在本版晋升 v0.36 的三张 `pilot` 能力卡。

## 6. 目标用户与使用场景

### 6.1 目标用户

- 使用 MyP-M-A 生成需求池、PRD、验收结论和交接提示词的产品负责人。
- 维护 MyP-M-A 合同、评测和版本状态的开发者。

### 6.2 核心场景

1. 用户给出带例外条件的需求，MyP-M-A 生成完整 PRD但不得扩大范围。
2. 用户把上一阶段结果交给 `/prompt`，提示词必须继承真实历史、候选身份和待决策项。
3. `/acceptance` 续测继承有效证据，同时保留失败、待补证和暂不验证状态。
4. `/idea` 使用内部压力测试，但不得把启发式分数或建议阈值冒充业务数据。
5. `/review` 对照意图、实现和测试时，准确区分实现偏离、文档过期、未验证和未经授权的范围变化。

## 7. 领域词汇与事实优先级

### 7.1 领域词汇

| 术语 | 定义 |
| --- | --- |
| 明确事实 | 用户、当前仓库、正式文件或真实工具结果已经给出，且来源和适用对象可定位的内容 |
| 事实冻结 | 在推理和成文前识别不可静默改变的事实，并在输出后核对其去向 |
| 逐字保留 | 技术字面值必须原样出现，不翻译、不四舍五入、不改枚举、不改变比较符 |
| 语义保留 | 允许压缩措辞，但主体、动作、条件、极性、数量级、时间边界和责任人不得变化 |
| 范围差异 | 输出相对输入发生新增、扩大、缩小、删除、重开或状态迁移 |
| 待决策状态 | 已指定责任人或尚未授权的选择，执行者不得代为关闭 |
| 内部启发式 | MyP-M-A 用于暴露弱项的评分或框架结果，不是用户行为或业务数据 |
| 最小充分 | 保留支持当前决策与风险控制所需内容，删除不改变结论的重复内容 |

### 7.2 事实来源优先级

事实冲突时不得静默覆盖，按以下规则处理：

1. 对象身份和实际状态以当前直接取证结果为准，例如 Git HEAD、产物哈希、文件内容和真实运行结果。
2. 产品范围、授权和待决策项以用户最新明确决定为准。
3. 正式 PRD、验证文档和版本状态文件只在其适用版本、对象和时间仍有效时继承。
4. 历史聊天、Memory 和旧摘要只用于恢复线索；与当前仓库或候选对象冲突时必须标为过期或待确认。
5. 推断、建议和外部案例不得覆盖以上任何事实来源。

当前直接证据与用户决定冲突时，同时展示“观察到的当前状态”和“用户期望状态”，等待确认或按已授权动作修正，不能二选一后隐藏冲突。

## 8. 事实冻结合同

### 8.1 必须识别的事实类型

| 类型 | 典型内容 | 保留方式 | 允许变化条件 |
| --- | --- | --- | --- |
| F1 对象身份 | 项目、版本、分支、HEAD、产物、路径、SHA256、任务 ID | 技术字面值逐字保留 | 直接取证证明已变化，并显式记录新旧值 |
| F2 范围与例外 | 包含项、不做项、阈值分流、保护的既有行为 | 条件、比较符和例外逐字或等价保留 | 用户批准范围差异 |
| F3 数值与口径 | 数量、单位、比例、分子分母、时间窗、时区、保留期 | 数值、单位、比较符和口径逐字保留 | 有新数据或用户确认的新口径 |
| F4 状态与历史 | 已完成、失败、待补证、暂不验证、已接受风险、待负责人决定 | 状态原名和责任人逐字保留 | 有同一对象的新证据或责任人决定 |
| F5 授权与禁止 | 允许读取、允许修改、不提交、不发布、停止点 | 动作和否定极性逐字保留 | 用户后续单独授权 |
| F6 证据边界 | 来源、时间、新鲜度、覆盖范围、mock/synthetic/placeholder | 语义保留，不得扩大证明范围 | 新证据补齐并通过身份核对 |
| F7 技术合同 | API、字段、枚举、状态机、错误码、配置键 | 技术标识逐字保留 | 正式需求或迁移合同批准 |

### 8.2 最小内部事实记录

事实冻结是内部检查，不要求每次向用户展示新表。正式复杂任务在推理阶段至少维护以下字段：

| 字段 | 说明 |
| --- | --- |
| `fact_id` | 本轮内部唯一标识 |
| `source` | 用户消息、正式文件、工具结果或证据路径 |
| `category` | F1～F7 |
| `source_literal` | 必须保留的原始字面值或最小语义 |
| `preserve_mode` | `literal` 或 `semantic` |
| `target` | 输出章节、表格、提示词或验收项 |
| `state` | 已确认、冲突、待确认、过期、仅建议 |
| `change_authority` | 用户、正式迁移、同源新证据或不可修改 |

仅在存在冲突、跨版本交接或高风险操作时，才把最小事实表展示给用户。普通单需求不增加可见章节。

### 8.3 事实冻结流程

```mermaid

    B --> C["生成当前阶段草稿"]
```

## 9. 范围变化门禁

### 9.1 差异分类

每个会改变产品、实现、测试或发布结论的范围项必须归入以下一种：

| 类型 | 说明 | 默认处理 |
| --- | --- | --- |
| `preserve` | 完全继承既有范围 | 可直接进入正式需求 |
| `add` | 新增输入未要求的功能或交付面 | 标为建议，等待授权 |
| `expand` | 放宽触发条件、扩大用户/数据/版本或取消例外 | 阻塞正式范围，等待授权 |
| `reduce` | 缩小既有覆盖或验收标准 | 标明损失和原因，等待授权 |
| `remove` | 删除既有功能、兼容路径或证据要求 | 默认不允许 |
| `reopen` | 重新打开已经确认的身份、方案或待决策责任 | 保持原状态，不重开 |
| `transition` | 根据新证据推进状态 | 记录来源、对象和失效条件后允许 |

### 9.2 范围差异最小记录

| 原范围与来源 | 候选变化 | 差异类型 | 依据 | 授权状态 | 最终去向 |
| --- | --- | --- | --- | --- | --- |
|  |  | preserve/add/expand/reduce/remove/reopen/transition |  | 已授权/待确认 | 本次范围/建议/排除 |

无差异时不输出空表，只写“本轮未改变既有范围”。

### 9.3 各阶段处理

- `/prd`：新增、扩大、缩小或删除都必须与上游事实比较；未经授权的项不能写入“本次必须实现”。
- `/review`：实现与意图不同不等于自动判 Bug；必须区分实现偏离、批准后的文档过期、未验证和待确认。
- `/acceptance`：不得在验收阶段新增 PRD 没有要求的普通交付面；发现新的安全风险时单列风险和后续决策，不伪装成原验收项。
- `/prompt`：只推进已指定下一阶段，不重新设计上一阶段，也不加入未授权任务。

EB-08 的硬保护：`> 50000` 行进入后台任务，`<= 50000` 行的现有同步路径必须保留；除非用户后续明确批准，不得改为全量异步。

## 10. 历史与状态继承门禁

### 10.1 继承最小元组

跨阶段交接和续测至少保留：

`对象 + 原状态 + 证据来源 + 证据时间/新鲜度 + 失效条件 + 决策责任人`

### 10.2 继承规则

1. 输入没有提供上一轮历史时写“未提供”，不得生成“上一轮已通过/已失败”。
2. `失败`、`待补证`、`暂不验证`、`已接受风险` 和 `待负责人决定` 不得改写为 `通过`。
3. 状态迁移必须有同一对象的新证据、明确责任人决定或已授权动作。
4. 候选身份已经锁定时，不因生成新提示词或验收摘要重新要求选择分支、版本或产物。
5. 证据因代码、依赖、配置、数据、环境或产物变化失效时，保留原历史并标记“证据失效”，不删除原结论。
6. Memory 与正式文件冲突时，以当前仓库和候选对象为准，并更新或降级 Memory，不把旧状态续写为当前事实。

EB-12 的硬保护：不得补造上一轮 Acceptance；“真实登录自启由产品负责人决定是否延期”必须保持为待负责人决定，执行者不得自行改成通过、阻塞或已延期。

## 11. 数值评分与阈值来源合同

### 11.1 数值来源分级

| 类型 | 定义 | 输出要求 |
| --- | --- | --- |
| N1 已确认事实 | 用户、正式文件或真实数据直接提供 | 保留数值、单位、比较符、分母和时间窗 |
| N2 可复算结果 | 基于已提供数据计算 | 写清公式、分子分母、去重和舍入规则 |
| N3 内部启发式 | MyP-M-A 压力测试等内部量表 | 明确标为“内部启发式”，分数必须绑定证据 |
| N4 建议阈值 | 为实验、发布或继续/停止提出的候选值 | 标为“建议值/待确认”，说明依据和阻塞阶段 |

### 11.2 强制规则

- 比较符、单位和条件是数值事实的一部分，例如 `> 50000` 不能压缩为“较大导出”。
- 没有分母、时间窗或样本代表性时，不输出失败率、采用率或市场结论。
- 已有真实日志、反事实实现或验收证据直接证明问题时，可以跳过压力测试总分并说明理由。
- `/idea` 的 `0～5`、总分 `40` 是内部启发式，不是业务指标；关键证据闸门不能被总分抵消。
- 业务继续/停止阈值只能来自用户、正式数据、已确认实验合同或有依据的建议值；无依据时作为执行前门禁。
- 竞品标价、原型喜欢度和朋友反馈不能换算成支付意愿、转化率或市场规模。

## 12. 最小充分交付与一致性终检

### 12.1 保留与删除规则

以下任一问题回答“是”，内容应保留：

1. 是否改变当前结论或选项取舍？
2. 是否提供结论所需的直接证据或证据边界？
3. 是否控制权限、安全、数据、迁移、发布或回滚风险？
4. 是否明确授权、停止条件、成功标准或下一步？
5. 是否属于当前入口不可省略的正式交付合同？

以上全部为“否”时删除或合并。不得为了简洁删除完整 PRD 的影响范围、失败链路、数据/状态合同、开发前验收，也不得删除 Acceptance 的对象身份、真实证据和缺口收口。

### 12.2 输出终检顺序

1. **入口与阶段**：交付物是否属于当前入口，未把计划冒充结果。
2. **事实字面值**：F1～F7 的承重事实是否保留，冲突是否可见。
3. **范围差异**：所有新增、扩大、缩小、删除和重开是否有授权。
4. **历史与状态**：是否补造历史、升级状态或替代责任人决定。
5. **数值来源**：数值、单位、比较符、分母、时间窗和阈值来源是否完整。
6. **文内一致性**：摘要数量、状态、结论和正文是否机械一致。
7. **最小充分**：是否存在不改变决策、证据、风险、授权或下一步的重复内容。
8. **入口保护项**：正式 PRD、深度 Review、实际验收和发布门禁是否仍完整。

摘要出现“3 项偏差”等计数时，正文必须恰好存在 3 个同口径条目；无法机械一致时改为不带数量的表达，不能保留错误计数。

## 13. 功能需求

### FR-001 入口前事实冻结

- 需求类型：Skill 运行时治理
- 入口：`/idea`、`/prd`、`/acceptance`、`/prompt`；`/review` 在意图/实现对照时适用
- 前置条件：存在用户输入、正式文件或工具证据
- 主流程：提取 F1～F7 承重事实，标记逐字或语义保留方式，再执行入口流程
- 分支：来源冲突时保留双方和来源；可直接取证时先核对；真正改变范围或授权时请求确认
- 异常：材料不可读或对象未锁定时降级为待确认，不生成替代事实
- 出口：生成当前阶段草稿并进入终检
- 日志/埋点：不新增运行日志；通过评测回答和评分证据验证
- 影响范围：现有全局硬门禁和四个入口 reference

### FR-002 `/prd` 范围差异门禁

- 需求类型：需求定义治理
- 入口：已有上游需求、现状或保护行为的 `/prd`
- 主流程：建立基线范围，分类候选差异，只有 `preserve` 和已授权差异可进入本次正式范围
- 分支：合理但未授权的变化进入候选方案或待确认，不进入开发必须项
- 异常：承重范围冲突未关闭时停在方案收敛版
- 出口：输出本次范围、延后项、不做项和必要的范围差异记录
- 保护：完整 PRD 的影响范围、失败态和验收合同不能因压缩删除
- 影响范围：`references/prd.md`

### FR-003 `/review` 与 `/acceptance` 范围保护

- 需求类型：评审与验收治理
- 入口：意图/实现/测试对照，或开发完成后的实际验收
- 主流程：按正式意图识别一致、实现偏离、文档过期、未验证、待确认和范围外变化
- 分支：新安全风险可以成为阻塞或后续候选，但必须与原验收标准分开
- 异常：对象身份或意图来源不一致时，不判实现偏离或通过
- 出口：最小修复、补文档、补证或返回 `/prd` 的明确去向
- 影响范围：`references/intent-implementation-audit.md`、`references/acceptance.md`

### FR-004 `/prompt` 与 `/acceptance` 历史状态继承

- 需求类型：交接与验收治理
- 入口：下一阶段提示词、续测、发布前补证
- 主流程：建立继承元组，只推进当前未关闭项，保留原状态、责任人和证据失效条件
- 分支：旧证据仍有效时继承；受变更影响时标证据失效；没有历史时标未提供
- 异常：不得补造通过记录、自动延期、自动接受风险或重新打开已锁定身份
- 出口：可直接执行的下一阶段提示词，或具有真实继承边界的验收结论
- 影响范围：`references/prompt.md`、`references/acceptance.md`

### FR-005 `/idea` 数值来源纪律

- 需求类型：价值判断治理
- 入口：压力测试、反馈统计、竞品/市场判断和实验建议
- 主流程：将数值归入 N1～N4，优先使用真实证据；内部评分明确标签和证据绑定
- 分支：真实问题已直接证明时跳过总分；无依据阈值进入执行前门禁
- 异常：分母、时间窗、单位或来源缺失时不输出伪精确结论
- 出口：证据判断、启发式评分或跳过理由、最小补证和继续/停止门禁
- 影响范围：`references/idea.md`

### FR-006 最小充分与一致性终检

- 需求类型：全入口质量治理
- 入口：所有正式输出渲染前
- 主流程：按八步顺序扫描事实、范围、状态、数值、摘要和入口保护项
- 分支：发现可修正的不一致时只修当前草稿；发现范围或授权冲突时停止并请求确认
- 异常：不得通过删除承重章节来满足长度目标
- 出口：事实一致、无无关重复且符合入口最低合同的输出
- 影响范围：现有 `guarded-output-scan`、`single-source-output` 和各入口局部合同；不新增可见入口

### FR-007 事实保真评测门禁

- 需求类型：评测与发布治理
- 入口：v0.37 实施批次和 Candidate 晋升
- 主流程：先运行内部定向失败样本，再执行 EB-08/12 稳定性、关联任务、保护性控制和一次 12 条候选面板
- 分支：只有受影响合同扩大或控制项回退时升级回归范围
- 异常：超时、执行器错误、空结果和评分失败单独记录，不计为行为失败；按现有长尾策略最多重试一次

### 18.4 12 条 Candidate 面板

定向门禁通过后，以 v0.36 的正式协议为准，对 v0.37 Candidate 执行一次 EB-01～EB-12：

- 执行：`gpt-5.6-luna medium`，工具禁用，超时 300 秒。
- 评分：沿用冻结的匿名、分维评分协议。

### 18.5 面板通过条件

1. EB-08、EB-12 关键违规为 0，且各自正确性不低于 `3/4`。
2. 12 条总正确性不低于 v0.36 的 `38/48`。
3. EB-01/02/06/10/11 不出现新的事实、范围、数值或状态关键违规。

### 20.5 不通过处理

- EB-08 仍扩大范围：回退 M2，保留失败用例，重新收敛 `/prd` 局部规则。
- EB-12 仍补造历史或状态：回退 M3，不用更长交接模板掩盖问题。
- 数值来源仍混淆：回退 M4 的评分规则，只保留明确来源标签和执行前门禁。
- 正式 PRD/Review 完整性回退：回退对应压缩规则；不接受“平均更短”作为补偿。
- 默认上下文增长：通过去重恢复；无法恢复则撤回新增运行时句子。
- 控制用例出现关键失败：停止 M5，扩大到受影响入口回归，不生成 Stable 结论。
- 执行模型或评分器不可用：记录无效样本并降级为待验证，不替换成未声明模型后继续比较。
- 12 条面板低于正确性基线但关键违规已关闭：保持 Candidate，逐题判断是否为新回退，不以统一总分放行。

## 21. 风险与范围保护

| 风险 | 等级 | 处理 |
| --- | --- | --- |
| 为事实保真而机械复述所有输入 | 高 | 事实记录默认内部化，只展示冲突和承重事实 |
| 局部规则在多个 reference 重复 | 高 | 每个入口只保存本地动作，全局定义继续复用现有硬门禁 |
| 为缩短文本删除正式合同 | 高 | EB-07/09 和内部控制作为硬保护，不用长度抵消 |
| 只针对 EB-08/12 过拟合 | 高 | 增加内部变体、关联任务、控制任务和一次完整 Candidate 面板 |
| 评分器偏好影响结论 | 中 | 关键事实使用逐项硬门禁，评分维度分开呈现 |
| v0.36 与 v0.37 文件混入同一提交 | 高 | M0 先冻结 v0.36 提交范围和 commit，再进入实现 |
| 事实冻结阻止合理创新 | 中 | 新建议允许输出，但必须标为候选并与已确认范围分层 |
| 旧事实被永久继承 | 高 | 继承同时记录对象、新鲜度和失效条件；同源新证据允许状态迁移 |

必须保护的既有体验：

- `/idea` 仍能做证据判断和压力测试，而不是只输出“数据不足”。
- `/prd` 仍能形成完整、可开发、可验收的正式文档。
- `/review` 仍先建立项目脉络，再给有证据的发现。
- `/acceptance` 仍能继承有效证据，并对真实候选做明确发布判断。
- `/prompt` 仍保持短、可执行和唯一代码块，不变成长篇事实转录。
