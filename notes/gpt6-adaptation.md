# GPT-6 适配记录

当前版本：v0.42 Candidate；首轮动态观察完成，普遍收益未成立。官方来源：[GPT-6 Astra 使用与提示建议](https://developers.openai.com/api/docs/guides/latest-model?model=gpt-6-astra)，核查日期 2026-09-05。

官方提醒 Skill 冲突、过早澄清、格式偏重及不相称验证可能影响表现。本版据此检查通用合同，不直接复制宿主系统提示词。

## 本版适配

必要问题才阻塞；已有同范围授权继续有效；真实合成数据测试与伪造执行证据分开；交接继承目标策略；正式文件完整而聊天不重复全文。用户指令优先于 Skill 默认建议，但系统/开发者安全要求不变。

主任务使用 ultra 不意味着所有工具任务都需要 ultra。首轮行为执行为 GPT-6 Astra ultra，Sol medium 为兼容对照；模型和强度由宿主选择，Skill 不切换模型、不要求特定 API。无子 Agent 工具可以单任务执行，不能伪称已并行或已关闭代理。

## 证据边界

实施与静态检查不能证明模型适配收益。R1 的 48 份回答全部有效，原始断言 GPT-6 为 82/85 → 84/85，Sol 为 79/85 → 78/85；独立正确性原分并未同步提高，部分判项有语义争议。R2 两模型的 2 题均 14/14 → 14/14，不能凭同一基线重评较高便宣称改进。不建议依据本页宣称 GPT-6 优于 Sol 或 Candidate 优于 Stable；完整边界见[验证记录](v0.42-adaptation-verification.md)与[实施计划](dev_plan_v0.42.md)。

R3 进一步区分文稿交付与实际落盘，题9/10四份候选回答断言通过；两组三轮本地工具流程验证了已有授权续做和撤权后只读。旧题9原判复核为状态歧义，三处只读声明已补真实轨迹，不能直接算证据伪造。仍有建议升级门禁、策略交接遗漏及评分争议，不以局部满分宣称通用适配完成。

R4仅补题2/4，两配置共4份新回答。协议继承在两配置样本中通过，GPT-6保持建议与门禁边界，Sol仍将额外失败测试作为发布前提。原断言两组均14/14却未覆盖该语义缺陷，因此同时保留独立质量和关键事件，不用结构满分宣称适配完成。153条全量回归按用户要求暂不执行。

## 后补阅读：规则应匹配新模型

来源：Eric Provencher，[Rethinking skills and prompts for GPT-6 Astra](https://x.com/pvncher/status/2095991462416490862)，2026-09-05 已读取正文。这是作者经验文章，不是本项目行为证据或官方发布门禁；阅读发生在 R1 冻结之后，不据此改写原题、评分标准或历史成绩。

文章的实用价值是区分“选中哪个 Skill”“执行时加载什么”和“何时算完成”。过宽的 description、反复常驻的规则、无条件重复验证与已经授权后仍暂停，都可能增加干扰。作者没有提供足以证明 MyP-M-A 应按固定比例减字的对照数据。

| 借鉴点 | MyP-M-A 处理 |
| --- | --- |
| 描述精确、减少多个 Skill 争抢触发 | 值得后续检查全局目录；本版 description 不变。实际改动必须重跑 34 条触发回归，不凭文章删除已安装插件。 |
| 根文件做导航，规则按条件加载 | 继续采用现有渐进加载；检查冲突和无效重复，而非只追求字符下降。 |
| 已授权的可逆动作连续完成，按任务风险验证 | 已纳入 v0.42，仍保留撤权、发布及生产操作边界。不能把模型更强解释为拥有更多权限。 |
| 完成条件包含实际执行与检查 | 明确真实运行和文字建议的差别；合成输入上的真实测试只证明对应范围，不外推真实业务效果。 |
| 按模型重新检视旧提示 | GPT-6 ultra 与 Sol medium 分开观察；必要的产品事实、完整 PRD、证据和职责边界不因新模型而删除。 |
