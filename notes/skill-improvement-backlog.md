## 2026-07-11 PCbuild 用户验证门禁记录

来源：

- PCbuild v0.1 在高保真原型和数据治理口径完成后，原门禁仍要求先完成 5～10 位真实目标用户测试才能生成开发计划。
- 用户提出是否可由子 agent 模拟，避免个人项目长期停在原型阶段。

判断：

- 子 agent 可以做认知走查、角色化任务、异常路径红队、文案理解和流程完整性检查，但不能证明真实新手的首次点击、完成时间、理解率或真实困惑。
- 对个人项目和早期原型，把真实用户测试一律设为开发前硬门禁会降低可完成性；门禁应根据项目风险、版本阶段和证据成本分层。
- 推荐拆分为两级：
  - `GATE-09A`：agent 原型预检。至少覆盖新手认知、核心任务、异常路径和文案误解；通过后可在用户授权下进入开发承接。
  - `GATE-09B`：真实目标用户验证。延后到可运行 MVP，不阻塞 dev plan 和 MVP 开发，但阻塞公开 Beta 或正式发布。
- agent 模拟结果必须标记为“模拟证据”，不得伪装为真实用户样本、完成率或用户原话。

后续优化候选：

- 在 `references/prd.md` 增加按风险选择验证层级的规则，避免机械要求所有原型在开发前完成真人测试。
- 增加 agent 原型预检模板，包含角色隔离、任务脚本、证据要求、严重度和转入真人验证的遗留项。
- 新增 eval：个人项目在真人招募困难时，应提出分层门禁，而不是无限阻塞开发或把 agent 模拟冒充真人测试。
