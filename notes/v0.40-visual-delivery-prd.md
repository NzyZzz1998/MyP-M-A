## 1. 背景与问题

MyP-M-A 已能在 `/review` 中要求项目关系图，并在 v0.39 验证过决策图表 pilot，但当前能力仍有四个断点：

1. 数值图表与架构、流程、状态等语义图解没有独立路由，容易用一种表达方式处理两类事实。
2. 可视化工具的“已安装、当前可调用、调用成功、版本、commit、许可证”没有统一真值合同。
3. 正式交付缺少统一的源文件、导出物、事实映射、双视口、离线和可访问性证据。
4. 视觉效果容易掩盖事实缺口；当前 v0.39 的正确性问题证明，美观不能替代正确性、证据和完整性。

v0.40 的目的不是增加更多图型，而是让“什么时候画、画什么、依据什么、怎样证明没画错、工具失败后如何继续”成为可执行合同。

## 2. 目标与成功标准

### 2.1 版本目标

- 建立“决策图表”和“语义图解”两条独立、可验证、可降级的交付通路。
- 将 diagram-design 接为可选 MIT pilot，不形成运行时硬依赖。
- 让正式图形交付具备事实映射、工具身份、可编辑源、可嵌入导出物和机械验证证据。
- 保持五个现有入口，不增加默认入口上下文预算。
- 正确性、证据纪律和完整性继续作为硬门禁；精炼度、耗时和视觉美观只作观察。

### 2.2 成功标准

1. 冻结数值任务逐值、单位、分母、时间窗和聚合校验无误。
2. 语义图解逐节点、逐边、方向、条件、状态、职责和基数校验无误。
3. 工具不可调用、身份不明或许可证不适用时，仍能通过 Mermaid、表格或文字完成原入口任务。
4. 正式交付同时保留自包含 HTML 与 SVG/PNG，并附 manifest、事实映射和浏览器验证结果。
5. `/review` 与 `/prd` 各完成至少一个真实复用；未完成前能力卡保持 `pilot`。
6. `SKILL.md` 与五入口正式装配不高于冻结基线；不得靠提高预算上限规避。

## 3. 方案收敛

### 3.1 候选方案

| 方案 | 说明 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- | --- |
| A. 继续仅用现有图表 pilot | 只扩展数值图表 | 改动小 | 无法覆盖架构、流程、状态和 ER | 不采用 |
| B. 双通路 + 可选适配器 | 独立处理数值与语义，工具可降级 | 事实边界清楚，可逐类验证 | 需要新增合同、模板和评测 | 采用 |
| C. 统一万能绘图器 | 所有信息进入一个视觉生成通路 | 表面统一 | 易混淆事实类型，难核验，外部依赖重 | 不采用 |

### 3.2 推荐方案

采用方案 B。路由先判断要回答的决策问题，再判断事实类型；混合任务优先拆成一张决策图表和一张语义图解，不拼成无法逐项核验的大图。

### 3.3 优先级

- P0：事实合同、路由分离、工具真值、降级、关键语义零错误。
- P1：正式交付物、双视口、离线、可访问性、重绘保真。
- P2：风格 profile、有限动效和更多图型。

## 5. 核心术语与不变量

| 术语 | 定义 |
| --- | --- |
| 决策图表 | 以冻结数值、单位、分母、时间窗和聚合为输入的比较、趋势、分布或相关性表达 |
| 语义图解 | 以节点、关系、方向、状态、顺序、职责和基数为输入的架构、流程、状态、时序、ER、泳道或数据流表达 |
| 事实映射 | 源事实与图中值、节点、边、标签或状态的一一对应记录 |
| 工具真值 | 安装、可调用、调用成功、版本、commit、许可证分别记录，不互相替代 |
| 正式交付 | 可编辑源、可嵌入导出物、manifest 和验证证据均齐全的输出 |

业务不变量：

- 图形是事实表达层，不是事实来源。
- 未知保持未知，不用视觉补全缺失信息。
- 工具失败不改变原入口的完成义务。
- 关键事实或关键语义错误为 0 才能通过。
- 图表与图解均不能替代正文中的结论、证据边界和开放问题。

## 6. 路由与流程

### 6.1 路由判定

1. 锁定读者、决策问题和来源。
2. 若核心事实是数值、单位、分母、时间窗或聚合，进入决策图表。
3. 若核心事实是节点、关系、状态、顺序、职责或基数，进入语义图解。
4. 两类事实同时存在时，先确定主要问题；均承重时拆成两张图。
5. 表格或文字更清楚、证据不足、许可证不适用或工具不可用时，不强制出图。

### 6.2 通路状态

```text
输入检查 -> 事实冻结 -> 类型路由 -> 工具探测 -> 生成 -> 事实核验 -> 交付验证 -> 回写
   |            |            |            |          |          |
   +--不足------> 待补证      +--不适用----> 表格 / Mermaid / 文字降级
                               +--失败------> 保留失败证据并降级
```

任何一步发现关键事实无法映射、图形制造歧义或验证失败，都必须停止正式交付，不得只修饰画面后宣称通过。

- 影响范围：README、CHANGELOG、roadmap、backlog、v0.39 progress/dev log/acceptance、evaluation history。

### FR-002 双通路路由

- 新增统一视觉交付 reference，定义决策图表与语义图解的触发和反触发。
- 明确混合任务的主要问题判断与拆图规则。
- `/review` 的项目地图默认优先语义图解；`/prd` 的流程/状态/ER 按需求风险选择；`/idea` 与 `/acceptance` 的冻结数值可按需进入决策图表。
- 不新增用户入口，不在每次调用中常驻加载视觉合同。
- 影响范围：`SKILL.md` 的按需导航、`references/capability-routing.md`、`references/review.md`、`references/prd.md`、`references/idea.md`、`references/acceptance.md`。

### FR-003 事实冻结与映射

- 图表冻结：指标、值、单位、分母、时间窗、过滤、聚合、缺失值和排序。
- 图解冻结：节点、边、方向、条件、状态、顺序、职责、基数和未知项。
- 每个视觉元素必须映射来源；推断和假设必须单独标识。
- 不允许补造关系、状态、负责人、时间顺序、数据库基数或数值。
- 影响范围：新视觉合同、manifest 模板、保真账本、评测 fixture 和自测。

### FR-004 工具真值与许可证

- 分别记录 `installed`、`callable`、`call_succeeded`、版本、commit、许可证、探测时间和证据路径。
- diagram-design 固定身份：缓存包 `2.5.1`、commit `9ec2497b85388ae6b31bd09c33ee11a71defcbca`、MIT、许可证 SHA-256 `895BFB578A43936A49792CCFEA515B0CF1F0F10AC9046186BC267FFC3BE480E5`。
- 保留 manifest `2.5.1` 与 skill frontmatter `2.4` 的身份告警。
- Lieflat Charts 仅在非商业许可适用且任务允许时作为可选 pilot。
- 影响范围：`references/tooling.md`、能力卡、注册表、工具探测记录和自测。

### FR-005 正式交付包

正式交付至少包含：

- 自包含、可编辑 HTML；
- 可嵌入 SVG 或 PNG；
- manifest：来源、哈希、工具身份、许可证、类型、尺寸、映射、假设、外部资源和降级结果；
- 桌面与窄屏截图；
- 浏览器结果：裁切、重叠、横向溢出、控制台、资源和离线检查；
- 可访问性：替代文本、颜色非唯一编码、静态回退；
- 重绘任务的保真账本。

缺少任一承重项时只能标为草稿或部分通过，不得标记正式交付完成。

### FR-006 输出验证与降级

- 决策图表执行逐值、单位、排序、聚合和缺失值核验。
- 语义图解执行逐节点、逐边、方向、条件、状态、职责和基数核验。
- 浏览器至少验证一个桌面视口和一个窄屏视口；外部资源必须为 0 或有明确许可、来源与离线行为。
- diagram-design 不可调用时，按任务降级到 Mermaid、本地 HTML、表格或文字；降级结果仍需事实核验。
- 影响范围：视觉验证脚本、自测、验收模板和交付 reference。

### FR-007 能力卡与上下文预算

- 保留现有 `visualization.decision-chart-adapter` 为 pilot，并新增 `visualization.decision-diagram-adapter` pilot。
- 能力卡只描述适用条件、输入、输出、证据、工具状态和降级，不复制 reference 正文。
- `SKILL.md` 当前接近预算上限，实施不得直接扩写常驻合同；优先通过替换导航或按需 reference 完成。
- 五入口 minimum/formal 装配相对冻结基线不得增长；若结构调整造成增长，停止该批并回退。

### FR-008 评测与晋级门禁

首轮评测至少覆盖：

1. `/review` 项目架构图，不补造组件与调用关系。
2. `/prd` 流程和状态图，保留取消、失败、重试和回退。
3. 冻结数值图表，逐值一致。
4. Mermaid 重绘，输出保真账本并识别语义损失。
5. 证据不足的漂亮架构图请求，拒绝补造。
6. 工具缓存存在但当前不可调用，真实降级。
7. 图表与图解冲突，明确主要问题或拆图。
8. 双视口、导出、离线、可访问性和外部资源验证。

晋级必须同时满足机械自测、定向行为、真实 `/review`、真实 `/prd` 和独立 `/acceptance`。单次最佳样本、视觉评分或字符下降不能替代。

## 10. 风险与回退

| 风险 | 影响 | 控制 | 回退 |
| --- | --- | --- | --- |
| 视觉掩盖事实缺口 | 错误结论更具迷惑性 | 正确性/证据/完整性硬门禁 | 表格或文字 |
| 外部工具不可调用 | 流程中断 | 分离安装与调用真值 | Mermaid、本地 HTML、文字 |
| 许可证不适用 | 商业使用风险 | 工具级许可门禁 | MIT 路径或本地实现 |
| `SKILL.md` 超预算 | 默认上下文回退 | 按需加载与逐批测量 | 回退该批导航改动 |
| 图过密或窄屏失真 | 不可读、不可嵌入 | 概览/细节拆分、双视口 | 多图或表格 |
| 工具版本漂移 | 结果不可复现 | 固定 commit、版本与哈希 | 冻结上一有效身份 |
