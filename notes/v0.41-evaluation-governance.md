## 生命周期

| 状态 | 用途 | 退出条件 |
| --- | --- | --- |
| core | 每个行为候选都要覆盖的长期核心 | 只有存在更强 successor 且完成独立审计后才能调整 |
| active | 当前有效覆盖 | 按合同或入口选择运行 |
| canary | 本版新增或变更的观察项 | 连续两个稳定版本后晋升、合并或归档 |
| archived | 保留历史证据，默认不执行 | 回退调查时可重新激活 |
| retired | 已被明确 successor 替代 | 不再进入面板，但保留原因和历史结果 |

不设置固定删题目标。只有题面等价、覆盖已由更强用例承接、历史独特失败信号已迁移，且入口、模式、风险和附件边界仍被覆盖时，才允许合并或归档。

初始状态登记是 v0.41 的治理决策，不伪造每条旧用例的创建版本。状态按 `suite + id` 独立保存，每次转换追加状态、版本和决策 ID；决策必须有原因及仓库内证据。归档/退役还需最后有效版本，退役必须指向有效替代用例。生成器不自动晋升，连续两个稳定版本后的复核由维护者发起，当前没有自动提醒服务。

面板角色与生命周期是两条轴：canary 未被本轮选中仍是 canary，active 被选为差量也不会变成 canary。动态选择排除 archived/retired；旧冻结面板仍含停用用例时直接报错，不偷偷缩减样本。

## 执行矩阵

| 变更 | 最低层级 | 是否默认跑模型 |
| --- | --- | --- |
| README、历史记录或纯展示变化 | T0 | 否 |
| 评测 schema、归属或生命周期变化 | T0 | 否；工具回归必须通过 |
| description、宿主触发配置变化 | T0 + T1 | 是，运行固定核心与触发集 |
| 单入口 reference / template / contract 变化 | T0 + T1 + T2 | 是，固定核心、合同差量和控制 |
| 入口核心或共享合同变化 | T0～T3 | 是，扩展到受影响入口 |
| 需要全量证明的行为 Stable 候选、重大回退调查或实际覆盖变更 | T0～T4 | 是，稳定集和挑战集分别完整运行 |
| 关键节点或外部竞争力研究 | T5 | 按研究协议运行跨模型和外部对标 |

默认行为基线为 `gpt-5.6-sol / medium / 每题 1 次`。前两次使用标准 300 秒、长任务 600 秒 SLA；第三次不设时间截止，继续等待有效结果。只有明确执行器错误或用户停止才记未完成，不自动追加第四次，也不生成占位答案。超时与重试成本单列，不能抵扣正确性。

T0～T5 是评测计划分层，不是调度器。模型调用、重试和停止动作仍由外部运行任务执行；`regression-workspace.ps1` 的 `coverage / targeted-max` 是执行档位，不能当成 T0～T5 的别名。T3 选择器已同时覆盖合同题和未绑定单一合同的场景题；T4 需先按账本筛选活跃组合。纯治理增量且运行时、题面、断言及覆盖不变时只跑 T0，不追溯要求已验收版本补全量模型测试。

## 评分与汇报

1. 正确性、证据纪律、完整性、事实保真：硬门禁，不能由其他维度补偿。
2. 决策清晰度、可执行性、有效返回率：质量门禁。
3. 重复度、字符数、完成时长、重试率：成本与体验观察。
4. 稳定集、挑战集、触发集、七维质量和外部对标分别汇报。
5. A/B 只比较双方共同有效样本，同时单列双方有效返回率和 SLA。
6. 不生成统一质量总分，不用更短或更快掩盖事实错误。

有效返回须同时有非空回答、合法逐项评分及无失败/未完成的执行状态。执行失败、取消、运行中或损坏元数据不能因残留文件存在就算完成。旧 `execution.json` 仅有耗时或缺失时，明确保留 `unknown`，按材料兼容并单列数量，不伪造执行成功。质量盲评准备与汇总复用此检查；历史报告不原地重算。

## 当前结构风险

- 24 个合同目前只有一条行为用例承载。它们不是自动补题信号，但修改这些合同时必须优先选择对应用例，并评估是否需要相邻控制。
- 7 个治理合同没有行为用例映射，当前由静态或工具自测覆盖；只有它们开始影响用户输出时才补行为用例。
- 63 条行为用例由场景组而非单一合同承载，保留用于跨合同复合场景。
- 当前没有 archived / retired 用例。v0.41 先建立生命周期，不为制造“瘦身数字”立即迁移历史用例。
- v0.41 发布快照为 28 条，高于默认 26 条目标；原因是保留 15 条工作模式差量和 4 条相邻控制，不把该快照规模固化为新默认。

## 本轮验证边界

本轮没有修改 `SKILL.md`、`references/`、`templates/`、题面、断言或合同映射，因此不触发新的模型行为 A/B。发布前只需完成：

- PowerShell 7 与 Windows PowerShell 5.1 的账本生成与 `-Check`；
- 账本投影漂移、策略约束、面板轮换不改状态、归档/退役决策与替代关系、入口场景覆盖；
- T3 标准快照写入、账本重建与既有合同校验的端到端兼容；场景组、用例、入口和状态必须同时匹配，不放行无归属的空合同；
- 空白/失败/取消/运行中/坏元数据拒绝，第三次长尾成功与历史缺状态兼容；
- 两套 PowerShell 的 `validate-skill.ps1 -Strict`；
- UTF-8、乱码、Markdown 链接、JSON / PowerShell 解析和 `git diff --check`。

既有 v0.41 动态行为结论和限制继续由 `notes/v0.41-evidence-impact.md` 管理。
