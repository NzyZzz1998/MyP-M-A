## 1. 背景与目标

MyP-M-A 已具备完整产品工作流、团队与全流程模式及分层评测。新的模型会更严格地执行已有指令，因此适配不能只替换模型名：需要检查规则冲突、提问停止点、授权继承、交付形式和验证成本，并用同模型对照证明修改有效。

本轮已确认的文本问题包括：短提示词特例禁止历史继承，模拟数据与伪造证据混为一类，旧评分强制无依据分数，团队原型例外缺少子场景限定。尚未证明这些问题在 GPT-6 上的发生频率；不将静态风险冒充新模型实测回退。

### 已确认决策

1. 本轮作为 v0.42，重点包括新模型适配。
2. 正确性、证据、完整性优先于精炼度；正式 PRD 不因篇幅长而降级。
3. 长短尾策略服务于可用、有效结果，允许按场景不同；保留评测第三次不因耗时自动终止的决策。
4. MyP-M-A 继续是通用产品 Skill，不增加 GPT-6 专属入口，不损伤 Sol 等既有模型的职责与事实合同。
5. R4后维护者补充：应主动发现遗漏的关键验收风险。新增门禁先以有依据的建议交负责人确认，不能冒充既定要求；已证实违反合同/安全要求时仍须阻塞，严重但待核实风险可建议暂缓受影响动作。防越界不能削弱产品判断力。

### 成功定义

已确认冲突在正反例中关闭；GPT-6 同配置下候选保留全部承重事实，必要问题不会漏问，非必要问题不阻断授权任务。结果可追溯且没有通过改评分口径伪造能力提升。可执行性、重复度、提问次数、字符和时长分别观察。

## 3. 角色与处理流程

维护者确认范围、关键取舍和发布；执行者按所选模式生成交付物；评测执行者看不到评分预期和别组回答；评分者只看匿名任务与回答；独立验收者复核候选身份、变更和证据。未实际安排的角色不记录为已完成。

处理顺序：锁定任务与模式 → 读取目标合同及有效策略 → 识别真正阻塞项 → 完成已授权工作 → 以真实证据验证 → 按读者交付 → 回写状态。用户改范围或撤回授权时，停止受影响动作并保留已完成事实；未知、失败、取消与未执行不写成通过。

## 4. 功能需求

### FR-001 交接事实与上下文保真（R1）

交接保留对象、模式、已确认范围、责任人、有效历史、影响本次结论的失效条件和授权。短模板可以省重复背景及无关身份，不能禁止承重事实。已确认通过且证据仍有效直接继承；产物或相关依赖变化只失效受影响结果；未提供历史保持未知。字段、路径、哈希和状态不改写。对应 AC-01。

### FR-002 按证据证明范围验收（R2）

验收清单可能不完整，主动检查遗漏风险。新增建议说明理由、影响、最小补证、成本/范围影响及待确认人；严重但未证实风险分开记录临时处置与核查条件；已证实违规不因清单漏项而降级为可选建议。新增要求正式确认后更新事实源，旧结论不被改写。该补充关联AC-01/03/07，不新增入口。

分别辨认测试输入是真实或合成、操作是否实际执行、证据是否直接支持结论。合成数据上的真实计算、保存或导出可支持限定场景通过；不能据此证明真实用户采用、正式数据准入、生产性能或实际付款。示例截图、计划和占位日志不能冒充执行证据。结论明确通过范围和未覆盖项，不把模拟输入一律拒绝。对应 AC-02。

### FR-003 断言与结果解释校准（R3/R4）

保留原始题面、回答、评分及归因记录。对冲突断言逐项记录原合同、模式/阶段、修改理由、允许等价表述与正反例；歧义未解决的项目标待确认，不删除以抬高通过率。只把重新评分作为独立评分版本展示，不宣称行为提升。

“断言通过率”“独立正确性维度”“有效返回率”“真实操作成功率”分别定义。有效回答不能靠非空文件一项判定；继续使用现有结构、执行状态与非占位检查。真实工具动作由受控工具夹具验证，不能在禁止 Memory 的回答环境判定 Memory 写后读成功。对应 AC-03/04。

### FR-004 按目标继承等待与重试策略（R5，经维护者澄清）

用户有效约束优先于 Skill 默认建议，目标评测协议优先于普通协作默认。不得用普通任务时限覆盖评测所要求的持续等待。前两次按冻结协议使用软/硬阈值；第三次不因耗时自动终止。用户停止或明确执行器错误应如实记录未完成，不承诺无限等待必定获得答案。

只对缺失或结构无效结果按协议重试；已经有效但内容错误的回答保留并评分，不能重试到高分。时间与尝试成本独立报告，不抵消正确性。普通可选辅助任务仍可超时降级。对应 AC-05。

### FR-005 模式职责与原型例外贯穿（R6）

已有 HTML 或代码不自动升级工作模式。team_pm 中设计团队承接原型时，PM 定义流程、状态、责任和验收，不被强制代做浏览器验证；用户明确要求代做时可执行。vibe_coding 继续关闭既有高保真与真实浏览器门禁。两种模式不改变业务范围、数据、权限、异常及验收语义。对应 AC-06。

### FR-006 GPT-6 的提问、执行与授权适配

信息充分时可零问直接交付，不凑固定问题数；优先从已授权材料核实。缺失会改变核心范围、业务规则、权限、安全或不可逆操作的决定时仍须明确提问，不能因为追求持续执行就代为决定。

同一已授权范围内不重复请求许可；完成可安全完成的准备工作，再在真正需要新授权的动作前停下。用户明确“只评审”“先提问”“不执行”时保持该限制；历史授权不扩展到新目标、外部写入或仓库公开。系统和宿主安全约束始终有效。遇到 Skill 指令冲突时说明适用规则与依据，不静默改变任务。对应 AC-07/08。

### FR-007 按读者与风险安排交付、委派和验证（R8）

聊天提供决策与核心证据，正式文件保持完整合同，证据附件承担详细定位。正式审计图保持可追溯要求，小图不重复扩展无关报告。未经验证不删除必要图例、状态、边或事实映射。

独立且有收益的任务才委派，使用受控并发并在完成后关闭；没有子 Agent 工具时直接执行或说明边界，不新增依赖。验证按变更范围选择，已完成有效检查不重复；出现新改动、新失败或未解决风险再扩大。正式发布必需门禁不因新模型能力更强而豁免。对应 AC-09。

### FR-008 评测事实源和模型建议（R7）

长期结果进入 evaluation-history，README/roadmap 引用同一有效记录。新记录区分快照身份、评分协议、任务覆盖、模型/强度、数据来源与未知；历史发布覆盖按原时点保留。已知字段矛盾用确定性自测拒绝，语义结论继续接受独立审计。

新执行逐题记录真实开始/结束时间、尝试、有效性与终止原因；旧批次均摊值保留原标签，不反推虚构逐题时间。GPT-6 使用建议单独放适配文档，标官方来源和验证范围，不变成其他宿主的硬规则。对应 AC-04/10。

## 8. 评测方案与停止条件

先冻结执行快照、逐断言合同及模型配置。评测校准和运行时优化分开对照：修订评分下比较基线与候选；同一原回答的新旧评分只用于解释评分变动。基线不能只沿用旧分数而候选套新标准。

推荐首轮为 12 个定向行为场景，覆盖 AC-01/02/05/06/07/08/09；每题独立上下文，GPT-6 Astra 使用与实际工作一致的 ultra 比较 v0.41/候选，Sol medium 做同题基线/候选控制。执行前单列运行数量、评分模型与成本预算；这是推荐配置，尚未启动或批准无限消耗。无需再增加 Luna 全量或穷举各推理强度。

工具动作、多轮授权和第三次等待另用受控夹具，不依赖真的挂起十分钟，也不能把脚本模拟当成模型行为证据。评估分别报告正确性、证据、完整性、可执行性、重复度、必要/多余问题、有效返回、字符、真实时长和重试成本，不生成统一总分。

单次没有差异不能宣称新模型适配成功；如初测无实际回退且目标行为改善，只对差异与波动项补样本，不挑最佳轮。若共用规则改变其他入口语义、出现关键新回退、description 改动或夹具不能代表承重行为，按既有策略扩大受影响回归；description 改动额外触发 34 条触发测试，本版默认不改。

发生关键错误则停止晋升，保存失败，做最小修复或回退对应批次。连续调整仍无收益时停止堆规则，保留已确认的治理修复；不能把没有跑到有效结果写成通过，也不因单次评分波动无限追分。

## 9. 风险与承接

- 规则减少后可能漏掉必要约束：保留正式交付控制样本和事实硬门禁。
- 修订断言可能偏袒本 Skill：先写正反例和理由，再盲评两版；争议项不直接豁免。
- ultra 成本可能过高：定向先行，执行前冻结预算；不能把主任务模型设置视为穷举授权。
- 单评分器可能有偏差：目标性检查交给独立复核；未验证前不对外宣称跨产品或跨模型全面领先。
- 候选输出更短但业务不完整：直接不通过，不用精炼度抵消。

开发承接见 [实施计划](dev_plan_v0.42.md) 与 [进度](progress_v0.42.md)。A0 仅为已知文档事实治理，不代表新模型适配、校验增强或行为修复已完成。v0.42 为本地 Candidate，未验收前不替代 v0.41 Stable 或修改历史发布记录。
