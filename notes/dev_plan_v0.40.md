## 4. 实施顺序与回退点

1. M0 先固化状态和冻结清单，不改运行时。
2. M1 先写统一合同，再建立入口接缝；预算增长立即回退 M1。
3. M2 接能力卡和工具真值；外部工具不可用不阻塞进入降级测试。
4. M3 建正式交付模板与机械验证，先用合成 fixture 验证。
5. M4 建评测与专用自测；出现事实错误时回退到最近通过的批次。
6. M5 进行真实 `/review` 和 `/prd` 复用，不直接修改真实项目业务文件。
7. M6 独立验收，只有全部硬门禁关闭后才讨论 Stable。

每个 M 为独立回退点。不得在前一批验证失败时继续叠加下一批。

回退分为两类，不得混写：

- 候选工作区恢复：先保存当前候选补丁或复制工作树，再撤销本批文件；这只恢复候选基线，不代表回到 Stable。
- Stable 快照回退：从 tag `v0.38.0`（peeled commit `80e6abe382bf7259c3cf1437a24aa76a20978cc6`）新建独立 worktree，并在该 worktree 运行 Strict 与上下文预算；不得用清理当前工作树冒充 Stable 回退。

## 5. 任务拆解

### M0 候选终止与基线冻结

- 目标：为 v0.40 建立不含歧义的起点。
- 任务：
  - 记录 v0.39 Candidate 晋升终止，不改写历史 tag。
  - 锁定 v0.38.0 commit、运行时文件哈希和上下文预算。
  - 建立 v0.40 候选文件清单与影响范围白名单。
  - 运行 Strict、预算和差异基线。
- 完成标准：状态文档一致，冻结清单可复算，工作区无未申报改动。

### M1 双通路与事实合同

- 目标：建立图表、图解和反触发的统一规则。
- 任务：
  - 新增 `references/visual-delivery.md`。
  - 扩展 `references/chart-delivery.md`，避免与统一合同重复。
  - 定义数值字段与语义节点/边的事实映射 schema。
  - 为四个产品入口增加最小路由接缝。
  - 测量 `SKILL.md` 与五入口上下文预算。
- 完成标准：两通路可判定、混合任务可拆分、证据不足可停止、默认预算不增长。

### M2 工具真值与能力卡

- 目标：把外部工具从“名称引用”变成可审计可降级能力。
- 任务：
  - 更新 `decision-chart-adapter`。
  - 新增 `decision-diagram-adapter`。
  - 在 registry 登记状态、输入、输出和降级。
  - 更新 tooling 与 capability routing 的六字段探测合同。
  - 验证 diagram-design 身份与版本不一致告警。
  - 验证商业任务不会误用 Lieflat Charts。
- 完成标准：安装、可调用、成功、版本、commit、许可证分离；不可用时不阻塞原入口。

### M3 正式交付与机械验证

- 目标：定义并校验一套可嵌入、可编辑、可复算的视觉交付包。
- 任务：
  - 新增 manifest 与保真账本模板。
  - 定义 HTML、SVG/PNG、截图和浏览器结果的命名与关联。
  - 增加逐值、逐节点、逐边和来源哈希检查。
  - 增加双视口、离线、外部资源和可访问性检查。
  - 增加错误、缺失、漂移和降级失败夹具。
- 完成标准：正常夹具通过，关键事实漂移、漏边、错误方向、远程资源和身份夸大均按预期失败。

### M4 评测与发布门禁

- 目标：证明合同在代表性任务中生效且不破坏原入口。
- 任务：
  - 新增 `/review` 架构、`/prd` 流程/状态、冻结数值、Mermaid 重绘用例。
  - 新增证据不足、工具不可调用、许可不适用和路由冲突挑战用例。
  - 为每项新增唯一合同和生命周期归属。
  - 建立 v0.40 发布面板和专用 self-test。
  - 运行受影响入口及相邻控制定向行为回归。
- 完成标准：关键事实/语义违规为 0；控制项无关键回退；不生成统一总分。

### M5 真实复用

- 目标：验证能力能在真实材料上提高理解，而非只通过合成测试。
- 任务：
  - 选取一个只读项目 `/review`，生成项目/模块关系图。
  - 选取一个已确认 PRD，只读生成流程或状态图。
  - 为两项交付生成 HTML、SVG/PNG、manifest、截图和验证记录。
  - 记录保留、合并、折叠、删除、新增和未知项。
  - 由维护者逐步查看，不把试点结果写回真实项目业务事实。
- 完成标准：两项交付事实映射闭合，浏览器与离线检查通过，用户能定位来源和未知项。

### M6 独立验收与版本决策

- 目标：判断 v0.40 是否可以晋升 Stable。
- 任务：
  - 独立锁定候选身份、完整 diff 和未跟踪文件。
  - 复算 M0～M5 全部门禁。
  - 审核真实复用、许可证、工具真值和降级。
  - 核对 README、CHANGELOG、roadmap、backlog、progress 和 dev log。
  - 输出通过、部分通过或未通过结论。
- 完成标准：全部硬门禁通过；否则保留 Candidate 或回退 v0.38。

## 6. 测试与验收

- 静态：Strict、上下文预算、JSON、PowerShell AST、UTF-8、乱码、Markdown 链接、敏感信息和 `git diff --check`。
- 合同：双通路正反例、工具六字段、许可、映射、降级和输出完整性。
- 行为：受影响入口 + 相邻控制，至少包含跨模型代表性抽样；不默认穷举。
- 浏览器：桌面与窄屏、无裁切/重叠/横向溢出、控制台/资源错误 0、离线可用。
- 人工：维护者检查真实 `/review` 与 `/prd` 的事实保真和理解增益。
- 回归：diagram-design 不可用、Lieflat 不适用时，原五入口仍能完成。

## 7. 开发日志约定

- 使用 `notes/dev_log_v0.40.md` 记录每批事实、决定、失败实验、验证和证据路径。
- `progress_v0.40.md` 只保留任务状态和门禁结论。
- 工具调用失败、许可证判断和视觉漂移需写清输入、实际结果和降级，不覆盖旧记录。

## 8. 风险与回退

| 风险 | 回退 |
| --- | --- |
| 默认上下文增长 | 撤销入口接缝，将规则留在按需 reference |
| 事实或语义错误 | 停止生成并降级为表格/文字 |
| 外部工具不可用 | Mermaid、本地 HTML 或纯文本 |
| 许可证不适用 | 禁用对应适配器 |
| 定向评测波动 | 保持 Candidate，不挑最佳样本 |
| 真实复用无理解增益 | 不生成图或回到表格/文字 |
