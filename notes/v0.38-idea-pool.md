## 推荐范围

采用“质量基础 + 两个只读适配试点”：

- 质量基础对五入口有效，但只在目标 reference 内实现，不新增常驻推理层。
- 企业适配层提供统一探测、取证、标准化、冲突和降级合同。
- 试点 A：GitHub 远端状态与本地仓库事实对照，用于 `/review` 或发布判断。
- 试点 B：结构化评测/产品指标数据取证，用于 `/idea` 或 `/acceptance`。
- 不实现具体 SaaS 客户端，不新增写入授权，不要求用户安装任何连接器。

## 成功标准

1. EB-12 连续 3 次无历史补造、状态改写或新增硬门禁。
2. EB-01/02/05/06/09/11 的证据、可执行性和精炼度定向复测无关键回退，并关闭已记录模式。
3. 每个无正式阈值的行动都能区分“确认值、建议默认、待负责人决定”，不再只写“执行前确认”。
4. 两个企业试点都能产出带来源、对象、时间、范围、新鲜度和限制的证据记录；工具不可用时诚实降级。
5. 默认五入口上下文不因适配层增长；企业 reference 与能力卡仅按需加载。
6. 不生成统一总分，不以字符下降抵消正确性、证据或正式交付完整性。
