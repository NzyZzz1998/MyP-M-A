# MyP-M-A 第二轮行为评测计划

## 目的

第一轮 10 条行为冒烟中，v0.18 通过 76/76 expectations，v0.17 通过 75/76；唯一差异是 v0.17 在 Web SaaS review 中使用英文证据状态。九条双版本满分说明旧 expectations 多为“是否提到”，不足以判断技能是否真正提升。

第二轮不修改 MyP-M-A 工作流正文，而是提高评测的可区分性。

## 用例

只运行以下五条：

| Eval | 场景 | 关键能力 |
| --- | --- | --- |
| 27 | UI/体验完整 PRD | 高保真原型门禁、跨模块影响范围、开发承接边界 |
| 28 | 部分通过验收 | 发布阻断、证据缺口、可执行补证 |
| 31 | 附件型 /idea | 数据口径、样本限制、证据闸门、范围收敛 |
| 32 | 后端/数据库 PRD | 租户隔离、幂等、状态流、保留与迁移 |
| 33 | Web SaaS /review | 产品工程地图、中文证据状态、候选问题分流 |

## 运行设计

- 对照：v0.17.0 快照与当前 v0.18.0。
- 每个版本、每条用例运行 3 次，共 30 次执行。
- 执行和评分子 agent 固定使用 `gpt-5.6-luna`。
- 输入附件、隔离限制、输出目录和评分规则对两版完全一致。
- 记录精确模型名、reasoning、token、耗时；工具未提供时明确标记为缺失，不使用输出字数冒充 token。
- 先进行程序化检查可验证的事实，再用独立评分器审查剩余语义 expectations。

## 判定门槛

- 任一版本单条用例低于 2/3 通过，视为该能力不稳定。
- v0.18 只有在五条平均通过率不低于 v0.17，且没有关键 expectation 回退时，才可称为无回退。
- 只有当 v0.18 在至少两条高价值用例中稳定领先，才能称为行为效果提升。
- 若两版仍普遍满分，继续增加反事实输入、精确事实校验和人工盲评，不把“满分”当作结论。
