# MyP-M-A v0.38 事实到行动与企业适配 PRD

## 1. PRD 类型

正式推进型内部治理 PRD。v0.38 吸收未发布的 v0.37 候选，并新增经过路线图确认的企业协作与数据工具只读适配试点。

## 2. 目标

- 保留 MyP-M-A 在决策清晰度和完整性上的优势。
- 修复证据不足却打分、未知长期悬空、重复表达和阶段交接擅自加门禁的问题。
- 让协作系统与数据工具的结果可以被标准化为可追溯证据，并安全进入现有五入口。

## 3. 非目标

- 不新增 slash command、PM 框架、通用 Agent 平台或连接器 Marketplace。
- 不实现 Slack、Linear、Jira、Notion、Figma、PostHog 的专用客户端。
- 不把 GitHub、飞书、数据分析插件或任何 MCP 变成硬依赖。
- 不默认执行外部写入，不自动提交、推送、发消息、改任务或更新文档。
- 不重跑所有历史模型、强度和用例组合。

## 4. 版本关系

- 稳定回退：远端 v0.36.0，HEAD `83e619c7ef7cd31cb782f142fa4b5ad65f01c115`。
- v0.37：作为 v0.38 的内部基线被吸收，不单独提交或发布。
- v0.38：完成本 PRD 全部门禁后进入独立 Acceptance。

## 5. 功能需求

### FR-001 事实保真继承

继承 v0.37 的事实、范围、历史、状态、数值来源和摘要一致性合同。明确事实不因结构化、压缩或工具接入而改变；新建议必须标为建议、假设或待确认。

### FR-002 证据纪律

- 只有存在正式量表、来源和证据映射时才能输出数值评分。
- 内部启发式不得伪装为业务事实，也不得作为单独立项依据。
- 没有正式阈值时，不生成看似精确的百分比、样本数或总分。
- 外部工具返回内容必须保留来源、捕获时间、对象、查询范围和直接限制。

### FR-003 可逆默认与行动合同

当信息不足但任务可以安全推进时，输出：

| 字段 | 要求 |
| --- | --- |
| 动作 | 当前可以直接执行的一步 |
| 负责人 | 已确认负责人；未知时写角色建议，不虚构姓名 |
| 输入 | 已有事实源或待补材料 |
| 产物 | 明确文件、记录或判断结果 |
| 默认建议 | 可逆、低风险且有理由的建议值；必须标为建议 |
| 确认点 | 哪个决策前必须由谁确认 |
| 通过/停止 | 可观察结果，不使用无来源伪阈值 |
| 证据位置 | 结果应回写的位置 |

不可逆、高风险或会改变范围的未知仍必须停下确认，不能用默认值绕过。

### FR-004 最小充分与去重

- 一个事实只完整表达一次；后文使用 ID 或简短引用。
- 章节只有在改变决策、证据、授权、风险或下一步时才保留。
- `/idea` 不默认同时输出证据表、压力总分、完整实验表和再次分流。
- `/prompt` 只传递执行所需事实、开放项、授权和停止条件，不复述整个工作流。
- 正式 PRD、深度 Review 和实际 Acceptance 的承重内容不因压缩删除。

### FR-005 阶段交接保真

- 交接只允许继承来源中明确存在的事实、状态、授权、未决项和停止点。
- 未提供的历史写“未提供”，不得固定生成“上一轮通过/失败/待补证”。
- 分支、HEAD、dirty、哈希等身份项只有在源任务或目标阶段确实需要时才成为门禁。
- 生成的下一阶段提示词不得新增会改变执行结论的硬前提。

### FR-006 企业适配信封

新增按需适配合同，所有协作/数据工具结果统一为：

```text
source_system / object_type / object_id / captured_at
version_or_ref / scope_or_filter / access_mode
facts / unresolved_conflicts / freshness / limitations
evidence_location
```

规则：

- 先探测“已安装、可调用、调用成功”，三者不得混写。
- 默认只读；写入需要对目标、内容和影响单独授权。
- 跨系统关联必须依赖稳定 ID、明确链接或用户确认，不按相似标题静默合并。
- 新旧证据冲突时保留双方和时间，以目标系统事实源或用户指定事实源裁决。
- 不可用时输出最小手工取证方案，不声称已经同步。

### FR-007 试点 A：协作项目证据

以 GitHub 远端仓库状态和本地仓库事实为真实只读试点：

- 读取远端分支/提交或公开仓库元数据。
- 读取本地 HEAD、工作区和状态文档。
- 明确两者对象、时间和差异，不自动推送或修改远端。
- 结果进入 `/review` 或发布判断的证据清单，而不是由工具自行给结论。

### FR-008 试点 B：产品数据证据

以结构化评测 JSON 为真实只读试点：

- 锁定文件、schema、统计对象、分母、时间与候选身份。
- 复算分维结果，禁止合并为统一质量总分。
- 将计算事实、评分器判断和产品解释分层。
- 结果进入 `/idea`、`/review` 或 `/acceptance`，并保留不可外推边界。

### FR-009 能力注册与按需路由

新增两张 `pilot` 能力卡：协作证据适配、产品数据证据适配。能力卡只声明触发、反触发、输入、输出、证据、工具类别、降级与评测映射；reference 继续是行为事实源。

## 8. 验收标准

1. v0.37 既有事实保真自测继续通过。
2. EB-12 三次有效样本关键错误为 0。
3. EB-01/02/05/06/09/11 定向复测不再出现无依据评分、纯占位行动或范围外门禁；完整性和正确性不回退。
4. EB-03/07/08/10 作为保护项，无关键回退。
5. 两个只读试点均产生完整适配信封；任何外部写入为 0。
6. 工具不可用、陈旧、对象冲突和跨系统 ID 不一致的反例均能安全失败。
7. 默认五入口装配不因企业适配 reference 增长；能力卡保持按需加载。
8. Strict、上下文预算、JSON、PowerShell、UTF-8、乱码、Markdown 链接、敏感信息和 `git diff --check` 全部通过。
9. 不生成统一总分，不宣称统计显著或全面领先。

## 9. 停止条件

- 为提高精炼度删除正式 PRD、Review 或 Acceptance 的关键合同。
- 用建议默认绕过资金、权限、生产写入、隐私或不可逆决策。
- 适配层要求安装特定插件才能使用五入口。
- 外部工具结果缺少对象、时间或范围仍被写成确认事实。
- EB-12 或跨系统冲突用例仍出现可重复关键错误。
