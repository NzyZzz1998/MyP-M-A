## 执行层与证据

| 类型 | 输入与执行 | 可证明的结果 |
| --- | --- | --- |
| decision | 固定题面与附件，同一任务可批次执行但声明共享上下文 | 事实、判断、交付内容；不证明 GUI 或服务操作 |
| artifact | 真实生成图/文件，保存来源映射与实际渲染范围 | 语义与产物交付；缺 GUI 证据不能称视觉通过 |
| file_task | 每配置独立合成目录，保留 current/archive 等身份，前后哈希 | 文件实际修改与未授权文件保留，不仅看“已完成” |
| multi_turn | 每个 Agent 只跑该场景；逐轮发送，控制器逐轮保存文件检查点 | 插单、恢复、撤权后的实际状态；不提前泄露后续输入 |
| policy_probe | 固定工具状态的判断题，不连接私人服务 | 授权/降级判断；不证明真实调用成功或无副作用 |
| trigger_probe | 只提供冻结 description，不加载 SKILL 正文 | 描述触发预测；不是 Codex/Claude Code 原生加载实测 |
| integration | 对应真实/故障注入夹具、原报告和 receipt | 实现/接入证据独立汇报，不给旧版本不存在的新增工具编造模型失败 |

`evaluation_collection.py` 统一 evals/cases/数组三种结构。`evaluation-collection-index.json` 派生来源/输入/断言/附件哈希、执行类型、轮数与精确重复组；不物理删题或隐式去重。所有源文件必须有归属；附件变更会使账本失效。Python 为评测准备器依赖，不成为使用 Skill 的运行时硬依赖。

本轮正式稳定与挑战 160 题在三个快照 × GPT-6.1 Sol medium / GPT-6 Astra medium 上使用共同输入。补充、触发预测和集成层另列分母，不能混合成统一优胜分数。外部 Skill 不在本次对比范围。

## 评分、重试与成本

正确性、证据纪律、完整性、事实保真不可由更短、更快抵扣。逐断言必须绑定原答位置；真实文件/多轮断言同时给前后产物与执行证据。没有观察渠道标未验证，不能把自述当事实，也不把“没有证据”直接判为已发生越权。

分别呈现决策清晰度、可执行性、重复度、字符数、完成时长和有效返回率；不生成统一质量总分。有效回答也可能低分，不因低分重试。评分者不看版本/模型标签和历史分数；分歧回到原答与证据复核，不选最高一轮。

沿用 evaluation-policy：最多 3 并发、每批最多 5 个独立单轮任务，多轮单独；前两次 300/600 秒 SLA，第三次不因长尾自动取消；没有结果时继续等待同一 handle，不另造答案。工具等待返回不代表模型超时。重试只处理缺失/无效结果，保留每次产物和耗时，不将批次总时长除以题数假装单题推理时长。

周额度耗尽不转付费，不复制认证或另用 API Key。派发前与每波完成后检查额度，接近耗尽时不再发新波，保存真实进度。闭合已完成 Agent，避免列表积压。
