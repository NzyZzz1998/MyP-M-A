## QuickRec Idea Pool

时间：2026-07-08

输入概况：

- 项目：`E:\codex\QuickRec`
- 来源：QuickRec project review 后产生的候选点。
- 输出文件：`E:\codex\QuickRec\doc\mypm-idea-pool-2026-07-08.md`
- 候选点：
  - Lite v0.1 是否需要隔离或删除区域/窗口录制底层代码。
  - CI 是否需要覆盖 `lite-master / lite-test` 分支。
  - 是否需要做诊断日志 / 错误导出能力。
  - Lite 打包体积是否需要继续优化。
  - Full 捕获后端是否需要升级，例如研究 WGC 等方案。
  - README / 文档状态一致性是否需要治理。

### 做得好的地方

- 成功把 `/review` 候选发现整理成需求池，而不是直接生成 PRD。
- 对每个候选点补充了证据等级、价值判断、当前阶段、压力测试分数、结论和最小下一步。
- 分流判断基本准确：
  - 现在直接做：CI 覆盖 Lite 分支、README / 文档状态一致性治理。
  - 进入 `/prd`：诊断日志 / 错误导出能力，且限定为最小版本。
  - 继续验证：Lite 底层代码隔离/删除、Lite 打包体积优化、Full 捕获后端/WGC 研究。
  - 暂不做：重型诊断中心、硬砍依赖、直接替换捕获后端等做法。
- 没有把技术研究型想法直接推进为正式需求，对个人项目和分支稳定性有保护。
- 对“诊断日志 / 错误导出能力”的范围控制较好：建议“打开日志目录 / 复制诊断信息 / 最近错误摘要”，不做复杂诊断中心。

### 暴露的问题

- 压力测试分数缺少明确分档标准。输出中有 `31/40`、`28/40`、`27/40`、`24/40`，但没有说明多少分进 PRD、多少分继续验证、多少分暂不做。
- “暂不做”不够果断。它说“没有永久否定项”，但 PM 判断中更重要的是“本阶段不做”。例如 Lite v0.1 不做 WGC、不做复杂诊断中心、不做大规模底层删除。
- 对“现在直接做”的事项缺少轻量任务化输出。CI 覆盖和文档一致性治理不一定需要 PRD，但可以直接拆成 Task。
- 需求池很有用，但后续应明确如何被 `/prd`、开发任务或下一轮 `/review` 引用。

### 拟观察方向

- 等 LetsMakeMoney `/idea` 也试跑后，再判断是否需要在 `references/idea.md` 中补充分数分档规则。
- 观察是否需要增加“阶段性不做”字段，避免只写“没有永久否定项”。
- 观察是否需要为“现在直接做”增加轻量任务输出能力。
- 观察需求池是否需要固定字段：关联 Review ID、后续入口、承接状态、关联 PRD/任务链接。
