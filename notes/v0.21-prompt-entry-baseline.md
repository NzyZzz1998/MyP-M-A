# v0.21 `/prompt` 入口基线

## 目的

在修改 MyP-M-A 前，记录真实使用中已经出现的提示词生成缺口。本记录来自 QuickRec、LetsMakeMoney、PCbuild 和 MyP-M-A 自身的连续使用，不把假设问题当作基线。

## 已观察到的失败

1. **只能在阶段末尾被动生成**：现有 `next-step-prompts.md` 只在阶段真正结束时加载；开发中途、Bugfix、续测和新线程交接仍需要用户反复说“帮我写提示词”。
2. **目标入口不明确**：生成的提示词有时没有在首行写出 `mypm /review`、`mypm /idea`、`mypm /prd` 或 `mypm /acceptance`，接收任务可能重新路由。
3. **提示词过长**：PCbuild 数据补证和 LetsMakeMoney 分阶段实现中，多次出现用户反馈“还是很长”“这么长你确定他搞得定”；提示词重复了已有文档内容。
4. **证据重复执行**：Acceptance 续测提示词容易重新展开全部清单，而不是继承仍有效证据，只列失效项和待补证项。
5. **交接不完整**：新线程提示词需要同时给正式事实文件、当前阶段、稳定决策、停止边界和 Memory 续接点，不能只提供背景摘要。

## 当前基线能力

- 已有精简执行版、完整审计版和人工验证版三档。
- 已能按 `/review`、`/idea`、`/prd`、开发承接、`/acceptance` 的完成状态推荐下一步。
- 尚无用户可显式调用的 `/prompt` 辅助入口，也没有 `next / continue / bugfix / acceptance / release / handoff` 场景契约。

## 本轮成功标准

- `/prompt` 是工作流辅助入口，不改变四个产品阶段。
- 用户只说“帮我写提示词”时也能自动触发。
- 默认产出一段可直接发送的精简提示词，不先写长篇分析。
- 提示词首行明确目标入口或真实内部子阶段。
- 引用正式文件和任务 ID，不复制已有 PRD、计划或验收全文。
- 继承仍有效证据，只列失效证据和剩余任务。
- 明确授权、停止点、验证和最终汇报。
- `handoff` 场景包含事实源和必要的 Memory 续接，但不保存完整聊天。
