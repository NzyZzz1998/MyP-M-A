# MyP-M-A v0.38 开发计划

## 实施原则

- v0.38 吸收 v0.37，远端 v0.36 为唯一稳定回退。
- 先失败夹具和局部合同，后适配层，再行为评测。
- 不新增入口，不批量实现 SaaS 连接器，不自动执行外部写入。

## 模块

### M0 基线冻结

- 记录 v0.37 dirty 基线、三方复测快照和 v0.36 远端身份。
- 冻结 EB-01～12 输入、候选与最终复测结论。

### M1 交付质量

- `/idea`：无依据评分禁用、可逆默认、行动合同。
- `/review`：证据来源与建议动作闭合，减少地图/入口/摘要重复。
- `/prd`：确认值与建议默认分层，正式范围保持完整。
- `/acceptance`：删除固定历史句，身份门禁按对象按需触发。
- `/prompt`：只继承已有状态和必要门禁。

### M2 企业适配层

- 新增适配信封、探测、只读、冲突、新鲜度、降级和写授权合同。
- 新增协作证据、产品数据证据两张 pilot 能力卡。
- 接入 capability routing 与 tooling，不进入默认五入口装配。

### M3 静态门禁

- 新增 4 条稳定用例和 3 条挑战用例。
- 新增 4 份合成 fixture。
- 建立唯一合同归属、自测正反例和 validator 接缝。

### M4 真实只读试点

- GitHub 远端/本地状态对照。
- 结构化评测 JSON 分维复算。
- 记录真实探测、调用、证据和降级；不写外部系统。

### M5 行为验证

- P0：EB-12 三次。
- 修复集：EB-01/02/05/06/09/11 单次，出现分歧再补至三次。
- 控制集：EB-03/07/08/10 单次。
- 新增企业适配用例单次，关键失败补至三次。

### M6 独立验收

- 复核完整 diff、证据身份、上下文预算、两项试点和行为边界。
- 通过后只更新为 v0.38 Stable（本地待提交），不自动 commit/push/tag/Release。

## 主要风险

- 质量规则继续增加上下文：通过局部 reference 替换重复句解决。
- 建议默认被误解为事实：强制来源标签和确认点。
- 企业适配沦为工具清单：只保留两个真实任务和可观察证据。
- v0.37/v0.38 历史混淆：明确 v0.37 未发布并被 v0.38 吸收。
