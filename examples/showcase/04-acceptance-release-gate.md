# 用例 04：自动测试全绿，也可以判定暂不可发布

> 类型：完全合成演示  
> 入口：`/acceptance`  
> 重点：锁定候选身份，只按实际证据判断

## 场景

虚构的 Windows 桌面工具 `ClipNote` v1.2 候选包完成了自动测试和打包，但部分 GUI、异常路径与升级行为缺少证据。

## 给 Agent 的输入

```text
mypm /acceptance

验收 ClipNote v1.2 候选包，判断是否可发布。

候选身份：
- 分支：release/v1.2
- HEAD：7f9c2d1
- EXE：artifacts\ClipNote-v1.2\ClipNote.exe
- SHA256：A7D4C980B570E69A26CFC1AE6A5A2B9DB7F662DF7D3B4C4FE92BBF7B15D9A118

已有证据：
- 128 项自动测试通过。
- 打包 smoke 通过，进程可以启动。
- 截图证明设置页可打开。
- 日志证明“保存成功”事件出现。
- 人工复测时修改保存目录后 UI 提示成功，但 config.json 仍是旧目录。
- 没有保存失败反馈截图。
- 没有通知区真实鼠标左键恢复证据。
- 没有从 v1.1 升级后保留配置的证据。

不要修改代码。必要时输出手动验证步骤。不要提交、推送、打 tag 或发布。
```

## 代表性交付节选

### 验收结论

**未通过，当前不可发布。** 候选包可启动不等于配置保存链路可用；已观察到“界面提示成功但配置未落盘”的真实冲突，属于发布阻塞。

### 分项结果

| 验收项 | 预期 | 实际证据 | 结论 |
| --- | --- | --- | --- |
| 候选身份 | 路径、版本与哈希可锁定 | 已提供分支、HEAD、EXE 和 SHA256 | 通过 |
| 基础启动 | 打包产物可启动 | smoke 通过 | 通过 |
| 设置页打开 | GUI 可进入 | 有截图 | 通过 |
| 保存成功 | UI 成功且配置真实落盘 | UI/日志成功，`config.json` 未变化 | **未通过** |
| 保存失败反馈 | 失败时明确提示且保留输入 | 未提供截图或日志 | 待验证 |
| 托盘左键恢复 | 真实通知区点击可恢复窗口 | 未提供 | 待验证 |
| v1.1 升级 | 保留兼容配置 | 未提供 | 待验证 |

### 最小修复与补证

| 缺口 | 最小动作 | 需要的证据 | 通过标准 |
| --- | --- | --- | --- |
| 保存成功假阳性 | 只有原子写入并读回确认后才显示成功；失败保留输入 | 失败注入日志、UI 截图、修改前后配置 | 成功时落盘一致；失败时不污染旧值、不误报 |
| 托盘左键 | 在锁定候选包上真实点击通知区图标 | 操作截图或连续日志 | 隐藏与恢复均成功，无重复窗口 |
| v1.1 升级 | 使用隔离配置执行一次覆盖升级 | 升级前后配置、启动日志、截图 | 支持字段保留，废弃字段按规则迁移 |

### 手动验证文档要点

1. 备份隔离环境配置并记录哈希。
2. 启动指定 SHA256 的候选 EXE。
3. 对配置目录注入不可写条件，修改路径并保存。
4. 截取失败反馈，核对输入保留、旧配置不变和错误日志。
5. 恢复权限后保存，再核对 UI、日志和文件三者一致。
6. 还原环境并终止进程；不得把修复后的新包证据归到旧哈希。

## 展示了什么

- 自动测试全绿仍不能覆盖点名的 GUI 和升级路径。
- UI、日志与配置文件冲突时，以实际落盘结果为准。
- “待验证”不会被写成通过，也不会因工具限制被删除。
- 验收结论与提交、推送、Tag、Release 授权分开。

## 可复测检查点

- [ ] 首行明确 `/acceptance`，并锁定给定候选身份。
- [ ] 结论不能是“部分通过但可发布”。
- [ ] 把保存假阳性列为阻塞，而不是普通已知限制。
- [ ] 生成可实际执行的失败注入和环境恢复步骤。
- [ ] 不声称已点击托盘、已验证升级或已进行远端操作。
