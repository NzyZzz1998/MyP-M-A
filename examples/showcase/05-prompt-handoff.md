# 用例 05：把验收缺口压缩成下一轮可执行提示词

> 类型：完全合成演示  
> 入口：`/prompt → Bugfix/定向复验`  
> 重点：短，但不丢候选身份、范围、验证与授权边界

## 场景

延续 `ClipNote v1.2` 验收结果。用户不需要重新讨论整个项目，只需要把保存假阳性修复交给下一轮 Agent。

## 给 Agent 的输入

```text
mypm /prompt

把本轮 ClipNote v1.2 验收结果整理成下一轮 Bugfix 提示词，只处理“保存成功但配置未落盘”的发布阻塞。保留候选身份、验证要求和禁止操作，不要带上托盘与升级补证。
```

## 代表性交付

入口判断：`/prompt → Bugfix/定向复验`

本轮仅生成提示词，未执行项目操作。

```text
实施/Bugfix

修复 ClipNote v1.2 设置保存假阳性，并完成定向复验。

基线：release/v1.2，HEAD 7f9c2d1。旧候选 EXE SHA256 为 A7D4C980B570E69A26CFC1AE6A5A2B9DB7F662DF7D3B4C4FE92BBF7B15D9A118，仅作失败证据，修复后必须重新构建并记录新哈希。

范围：只处理配置原子写入、失败反馈和保存结果日志。成功提示必须在写入并读回一致后出现；失败时保留用户输入，不污染旧配置。

验证：覆盖成功、无变化、目录不可写和读回不一致；提供 UI 截图、日志及配置前后对照，并回归既有设置保存测试。结束时恢复 ACL、配置和进程。

停止条件：发现需要迁移配置结构或改变 v1.2 业务范围时停止并汇报。不要处理托盘或升级，不提交、不推送、不打 tag、不发布。成功标准是四条保存路径均有一致证据，且不再出现成功假阳性。
```

## 展示了什么

- 只继承本轮需要的事实，没有把托盘和升级补证带入 Bugfix。
- 明确旧哈希只是失败证据，修复后不能复用旧产物身份。
- 同时包含范围、验证、环境恢复、授权和停止条件。
- 正文足够短，可以直接发给下一轮 Agent。

## 可复测检查点

- [ ] 首行明确 `/prompt` 的实际去向。
- [ ] 只有一个可复制代码块，正文不再调用 `/prompt`。
- [ ] 保留分支、HEAD 和完整 SHA256，不改写数字。
- [ ] 不包含托盘与升级任务。
- [ ] 明确不提交、不推送、不打 tag、不发布。
